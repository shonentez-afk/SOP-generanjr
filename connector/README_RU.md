# SOP SharePoint Connector — этап 1

Отдельный Windows-кандидат, созданный от принятой Stage41. Исходный HTML, модули конструктора, настройки ИИ, Excel-шаблоны и main не изменяются.

## Назначение

- Подключение к разрешённому HTTPS-сайту с текущей учётной записью Windows через HttpClientHandler.UseDefaultCredentials.
- Только GET: название сайта, метаданные семи заранее определённых хранилищ, типы 70 бизнес-полей, внутренние имена и EntityPropertyName, обязательность, доступность записи, настройки версий.
- Раздел «Поручения» логически соответствует списку «Задачи»; пустой дубликат не используется.
- Разбор Atom XML вместо проблемной десериализации Id/ID. Запрет перенаправлений и перехода на другой хост или сайт по OData next. TLS не ослабляется. Нет HTTP-сервера на ПК, загрузки документов, записи в SharePoint, сохранения паролей, телеметрии или обращений к ИИ.
- Точный адрес вводится пользователем локально; корпоративские пути, реальные GUID, скриншоты и документы не включены в репозиторий.

## Сборка и проверка

Требуется разрешённый .NET 10 SDK для сборки и .NET 10 Desktop Runtime для запуска на Windows. Не устанавливать и не запускать стороннее ПО в обход политики предприятия. Кандидат не подписан корпоративным сертификатом; отсутствие разрешения на запуск — блокер, а не повод менять настройки защиты.

```powershell
dotnet run --project connector/Tests/Sop.SharePoint.Tests.csproj -c Release
dotnet build connector/Windows/Sop.SharePoint.Windows.csproj -c Release
dotnet publish connector/Windows/Sop.SharePoint.Windows.csproj -c Release -r win-x64 --self-contained false -o connector-publish
```

В приложении указать адрес разрешённого сайта, подтвердить подключение и посмотреть вкладки «Хранилища» / «Проверка полей». OK означает соответствие проверенной части схемы, а не доказательство прав записи. При несоответствии вывести результат, не исправлять сервер автоматически. Значения Choice, Lookup-цели, форматы дат и разрешения будут проверяться отдельно. Проверка ожидает название «Платформа СОП и TWI». Поля ожидаются согласно согласованному проекту, фактическое расхождение необходимо исследовать, а не автоматически изменять столбцы.

## Границы этапа

Тесты на синтетическом Atom XML не обращаются к корпоративной сети. Реальная авторизация из .NET-клиента, GUI и соответствие схемы конкретного сайта требуют пользовательской приёмки. Проверенная авторизация PowerShell не доказывает, что корпоративная политика разрешает новый exe. При блокировке запуск не обходить.

Пилот на рабочем ПК подтвердил загрузку и чтение TXT, XLSX, MERGE двух текстовых метаданных, сохранность рабочих частей и исходных связей первой XLSX-копии. После MERGE XLSX отличался только customXml/item3.xml. SHA-256 целой Office-книги может меняться из-за штатной синхронизации свойств. Следующий модуль должен различать неизменяемые исходники (строгий хэш) и Office-экспорты (проверка частей, типов и связей, только проверенные служебные изменения). История версий, TWI, полный L1 и Outlook ещё не приняты. Не связывать Connector с Stage41 до разрешённого запуска и испытаний.
