# Архитектурная проверка Stage 26 — состояние перед пользовательской приёмкой

**Текущая база:** PR #20, commit `3dce33924c9c4c5fab8beb0ea2c244530284c049`. Исторические аудиты Stage18–25 описывают состояние на даты их создания, не актуальную недоделанность Stage26.

## Реальные границы и зависимости

| Слой | Действующая ответственность |
|---|---|
| Core / snapshot | структура шагов, идентификаторы, безопасные копии для экспорта и расчётов |
| Shared / media | Blob/dataURL и хранилище изображений, без привязки конвертера к ISO или Excel |
| Editor / photos | действия, ключевые моменты, разметка и исходные фото |
| Documents / review | черновики, версии, публикация, история наставника, база браузера и сетевая папка |
| Safety | 60 встроенных ISO 7010 |
| Excel | локальная ExcelJS, фото/OOXML, XLSX без мутации живого редактора |
| FRV | RAW/фактические длительности отдельно от AI-подсказок/кандидатов в стандарт |
| AI transport | тот же Yandex Cloud-прокси, model/task request; HTTP timeout/body/errors/fallback |
| AI protocol | JSON/задачные схемы, отклонение пустых и некорректных ответов |
| AI presentation | сравнение предложений и подтверждение перед заменой данных |
| TWI | автоматическая генерация четырёх этапов из СОП, защита ручных поправок |
| Bootstrap | соединяет модули в едином автономном интерфейсе |

**Важное уточнение:** 50 исходных JS-файлов собираются в одну общую JS-область имён. Это осознанный компромисс ради одного автономного HTML с `file://`. Нельзя выдавать такое исполнение за полностью независимые ES Modules. Гарантию отсутствия обычных регрессий дают проверка состава manifest, воспроизводимая сборка, проверки JavaScript, Node/Python и настоящая браузерная регрессия. Дальнейшая модульная переработка без воспроизводимой ошибки не является обязательным пунктом перед пользовательской приёмкой.

## Исправлены подтверждённые архитектурные риски

- Фото не удаляются на экспорте/импорте XLSX; редактор разметки не зависит от удаления библиотеки пиктограмм.
- Подсказки и вывод ИИ не должны записываться без проверки адресата и версии документа.
- Ручные поправки TWI не заменяются повторной генерацией без сравнения/выбора.
- Существующий СОП нельзя перегенерировать поверх фотографий без решения пользователя.
- ФРВ-измерения не теряются при новом AI-цикле, подсказке отдельной строки или повторном анализе.
- JSON-маркеры `null`/`keep` не становятся автоматически применимыми исправлениями.
- Системная ошибка/лимит прокси не выдаётся за недоступность конкретной модели и не вызывает двойной запрос.
- Отсутствие Key Points, фото или СИЗ не трактуется как обязательный дефект без контекста.

## Объективные границы проверки

**Закрыто автоматически:** 68 unit, полный Linux Chrome регресс, нативный Windows Chrome \`file://\`, 60 ISO, ExcelJS, 10/10 встроенных проверок Windows-библиотеки, отсутствие JavaScript pageerrors.

**Не может быть проверено из GitHub Actions:** фактические разрешения вашего Yandex Cloud Function; прокси, доступный только из вашей корпоративной сети; авторизация и права записи в вашу сетевую папку. Это не программный дефект и не основание утверждать, что в вашей среде всё уже проверено. Выполняется вручную по инструкции для Stage26.

**Не входит в задачу:** миграции пользовательских архивов прежних выпусков, поддержка одновременно установленных старых версий, мобильный интерфейс, самостоятельный мастер создания TWI.

**Следующее событие:** пользовательская браузерная приёмка. До неё новых кодовых этапов не планировать; по её итогам исправлять только воспроизводимые ошибки.
