# Stage 27 — интеллектуальный помощник СОП (кандидат для приёмки)

**База:** Stage 26 main (`releases/stage26-final-browser-candidate.html`). Все существующие модули генерации СОП, TWI, ФРВ, Excel, фотографий, облачного транспорта/моделей и сетевой библиотеки сохранены. Модельная маршрутизация прокси на стороне Yandex Cloud по решению пользователя выключена, 4000 max output tokens и strict completion включены. Эта реализация **не меняет** прокси или его переменные окружения.

**Ветка:** `feature/stage27-intelligent-assistant-20261119`.

**HTML:** `releases/stage27-intelligent-assistant-browser-candidate.html`, автономный файл для настольного Chrome/Edge через `file://`. Сборка: `python tools/build_stage27.py` по `src/app/stage27-parts.json` (54 исходных JS-модуля). Вся прежняя HTML-оболочка, пиктограммы, ExcelJS и CSS идентичны Stage 26. Базовые Stage 26 исходники не изменены; для расширения сохранения добавлены копии модулей `stage27-db`, `stage27-draft`, `stage27-library`.

## Интерфейс: одна зона проверки СОП

После пользовательской проверки отдельная крупная панель «ИИ-помощник» и кнопка «⋯ Дополнительно» **убраны**. Под существующей строкой действий **«Сгенерировать СОП» / «Проверить весь СОП»** постоянно видны четыре аккуратные кнопки в стиле конструктора: **«❔ Уточнить СОП»**, **«🧩 Логика шагов»**, **«📚 По аналогии»**, **«🕘 Сравнить версии»**. Они не вызывают всплывающее меню: нажатие открывает соответствующий инструмент **внутри исходного блока результатов проверки**, повторное нажатие скрывает дополнительные результаты. Одновременно открыто только одно дополнительное направление. Прежняя проверка СОП, список замечаний, споры с наставником и генерация документов работают отдельно без изменения поведения. Правило: единый блок результатов без дублирующих больших панелей.

## Возможности

1. **Диалог уточнений.** Кнопка «Найти важные уточнения» запрашивает до 6 конкретных вопросов по текущим шагам. Инженер вводит ответ и отдельно его подтверждает. В черновике и сохранённой библиотеке хранится текст ответа и признак подтверждения.
2. **Точечные предложения.** Кнопка «Предложить точечные изменения» использует только подтверждённые ответы; модель может предложить изменение только `action`, `reason` или `successCriteria` существующего шага. Каждый вариант показывает «Сейчас / Предлагается» и собственный checkbox, по умолчанию выключенный. Модель не может менять время, фотографии, ISO, ФРВ и TWI; валидация проверяет ID шага, исходное значение, ссылку на подтверждённый ответ и версию документа. Смена данных в течение запроса или после выдачи предложения не допускает применения устаревшего ответа.
3. **Наставник 2.0.** Дополнительная проверка смысловых противоречий и неясностей до 18 шагов за раз. Замечания показываются отдельно от старого наставника, не заменяют его историю и не утверждают безопасность СОП. Кнопка «Объяснить замечание» делает отдельный запрос по выбранному замечанию. Важные факты должны подтверждаться инженером.
4. **По аналогии.** Полнотекстовый локальный поиск по названиям/описаниям/шагам **только опубликованных** СОП. Произвольный текст документов не отправляется модели при поиске. После выбора конкретного аналога и явного нажатия «Создать» отправляется компактный текст выбранного утверждённого СОП и целевого описания; предложенный результат проходит существующую валидацию и штатное окно выбора «отмена / добавить / заменить». Исходные фото, времена и параметры безопасности не переносятся автоматически. Это лексический, не семантический поиск.
5. **Сравнение редакций.** Локальный детерминированный diff шага/поля с указанием необходимости проверить TWI, фото, ФРВ или безопасность. Отправки в облако нет. Сравнивает текущий редактор (включая несохранённые изменения) с выбранной версией из локальной библиотеки.

## Безопасность и ограничения

- Не применяются непроверенные предложения. Автоматического утверждения или публикации нет.
- Опубликованный/архивный СОП не редактируется новым помощником. Для работы создайте черновик или новую версию.
- Существующие загруженные фотографии не отправляются ИИ. Мультимодальность, фотоанализ, видео, голос и полный RAG не добавлялись.
- Прокси прежний. Новые типы запросов используют прежний `aiAsk()` с `task` и текстовым JSON.
- Живой корпоративный Yandex Cloud и сетевую папку могут проверить только пользователи в своей среде. CI использует подставные ответы `aiAsk` и отключает сеть.
- Для больших документов смысловая проверка ограничена первыми 18 шагами (на экране предупреждение); поиск аналогов локальный, без облачных embeddings.
- Новый релиз — кандидат Stage 27, не принятое пользователем обновление main.

## Автоматическая проверка

- `python tools/build_stage26.py --verify-release --verify-static` — Stage 26 остаётся неизменным.
- `python tools/build_stage27.py --verify-release --verify-static` — воспроизводимый автономный файл и неизменная HTML-оболочка.
- `python -m unittest discover -s tests -v` — прежние и Stage27 Node/Python контракты.
- `python qa/stage27_browser_smoke.py` — полная Stage26 Chrome регрессия на Stage27 + подтверждения, устаревшие ответы, локальные аналоги, отмена, сохранение, diff.
- Windows Actions job: Stage26 Chrome Windows `file://` регресс на Stage27, локальные ExcelJS и ISO.

## Ручная приёмка

1. Загрузите Stage27 автономный HTML, откройте Chrome/Edge с ПК (без дополнительных папок и сервера). Под основными кнопками нажмите нужное действие — «Уточнить СОП», «Логика шагов», «По аналогии» или «Сравнить версии». Кнопки видны постоянно и открывают результаты внутри прежнего блока проверки, без дополнительного меню.
2. На тестовой операции нажмите «Найти важные уточнения», подтвердите ответ. Предложите точечную правку; проверьте предпросмотр, чекбокс, отмену (не отмечайте), затем применение. Проверьте сохранение времени и фотографий.
3. Нажмите «Проверить логику СОП», затем «Объяснить замечание». Убедитесь, что рекомендации не применяются сами.
4. В библиотеке откройте опубликованный СОП, создайте новый черновик и найдите аналог. Убедитесь, что без подтверждённого отличия параметры оборудования не копируются. Проверьте «Отмена/Добавить/Заменить» и сохранность фото/времени при «Добавить».
5. Создайте новую версию из существующего СОП; сравните с предыдущей редакцией и проверьте уведомления о TWI/ФРВ/фото.
6. Сохраните черновик, перезапустите HTML, восстановите черновик и откройте из библиотеки: подтверждённые уточнения и замечания должны сохраниться.
7. Повторно проверьте реальные SOP→TWI, ФРВ, фоторазметку, экспорт XLSX с фотографией и наличие всех 60 ISO.
8. Проверьте работу текущей облачной функции. Модельную маршрутизацию в Yandex Cloud не включайте в рамках Stage 27.

**Правило до приёмки:** не объединять с main и не менять действующий прокси.
