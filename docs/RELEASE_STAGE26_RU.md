# Stage 26 — финальная техническая приёмка Конструктора СОП перед проверкой в браузере

Дата: 19 ноября 2026. **Принят в main:** PR #20, коммит `3dce33924c9c4c5fab8beb0ea2c244530284c049`. Единственная актуальная исполняемая версия: `releases/stage26-final-browser-candidate.html`.

## Результат и границы выпуска

Stage 26 закрывает текущий пакет инженерной работы A1–A4 и завершает доступную без инфраструктуры пользователя часть A5. Программа открывается как один автономный HTML двойным щелчком в Chrome/Edge на ПК через `file://`. Обязательной установки, backend-сервера, отдельных файлов ExcelJS, базы ISO и ES imports нет. Внутри сборки 50 функциональных JS-модулей.

**Чего этот выпуск не заявляет:** подтверждения связи с реальным корпоративным Yandex Cloud или фактического доступа к сети предприятия. У GitHub Actions нет учётных данных и пути к сетевому диску пользователя. Это финальные пункты приёмки **в его браузере** по `docs/BROWSER_ACCEPTANCE_STAGE26_RU.md`; автоматический зелёный CI не подменяет их.

## Выполненные задачи

1. **A1 — модульная сборка.** `src/app/stage26-parts.json`, `tools/build_stage26.py` и 50 JS-модулей. Релиз воспроизводится побайтно, старые стадии остаются тестовыми контрольными точками. Исполняемая архитектура использует общую JS-область, а не ES imports: это необходимо для автономной работы в `file://`, **не является полной изоляцией модулей по процессам или пространствам имён**.
2. **A2 — безопасные данные.** Не менялись контракты снимков экспорта, фото/IndexedDB, редактирования разметки, библиотеки, истории замечаний, локальной ExcelJS и 60 ISO 7010. Сквозной регресс подтверждает фото внутри XLSX, повторное чтение и отсутствие модификации живых шагов.
3. **A3 — AI-протокол и HTTP.** `src/modules/ai/stage26-transport.js` ограничивает размер тела ответа, держит таймаут до окончания его чтения, различает ошибку формата JSON, сетевой сбой и коды HTTP. Модель переключается на резервную только при явно распознанной недоступности **конкретной модели**; 401/403/429/общие 5xx не вызывают скрытый второй запрос. Таймауты и размер запросов, модели, URL Yandex Cloud, промпты и структура тела запроса сохранены. Самовольных повторов нет.
4. **A4 — применение ИИ без потери данных.** Существующая защита Stage22–25 от устаревших ответов и перезаписи СОП/TWI/ФРВ дополнена `src/modules/frv/stage26-proposals.js` и `stage26-study-ai.js`. Подсказки отдельной строки и полный анализ теперь показывают выбор: отменить, заполнить только незаполненные поля, явно заменить производные поля; полный анализ можно сохранить без изменения строк. Исходное RAW-действие, фактическое `durationSec` и доказательства никогда не записываются из ИИ. Если СОП/ФРВ изменились во время диалога, предложение отклоняется.
5. **Меньше ложных замечаний.** `src/modules/review/stage26-deterministic.js` не требует искусственно придумывать Key Points (действующий промпт разрешает 0–3), фото и СИЗ, когда нет фактического основания. Проверки действия, времени, реальных критичных моментов и дублирующихся шагов сохранены.

## Что делать дальше

Больше инженерных изменений **до проверки пользователя** не требуется. Нужно открыть файл в браузере на своём компьютере и выполнить список из `docs/BROWSER_ACCEPTANCE_STAGE26_RU.md`, отдельно проверив живой Yandex Cloud-прокси и папку на корпоративном диске. По результату фиксировать только конкретные подтверждённые дефекты, а не начинать новый этап или поддерживать историю старых пользовательских установок.

СОП — основной документ. ФРВ необязательна; TWI автоматически создаётся **из текущего СОП** и может быть вручную уточнена после генерации. Телефон не рассматривается.
