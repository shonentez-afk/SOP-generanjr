# Аудит организации ФРВ и «Анализа ФРВ» — Stage32.2

Дата: 20.11.2026. Источник: принятая ветка `main`. **Это анализ, а не реализация:** работающий код, экспорт XLSX, СОП, TWI и настройки ИИ не изменялись.

## 1. Как устроено сейчас

### «⏱ ФРВ» — обычный лист хронометража

- Источник: `state.steps[].durationSeconds` и `state.steps[].frv={vdc,m2,m1,move,comment}` из редактора СОП; `src/modules/frv/stage20-measurements.js`.
- Таблица 8 колонок: номер, действие, длительность, флажок ВДЦ, М2, М1, перемещения, комментарий.
- Паспорт бланка (`state.frvMeta`): наблюдал, качество, условия, назначение; **8 дополнительных целевых показателей**.
- Данные записываются в лист **«ФРВ»** автономного XLSX; `src/modules/excel/stage32-export.js` и отображаются в предпросмотре `src/modules/preview/stage19-preview.js`.
- Полный анализ AI не является частью этого листа.

### «📊 Анализ ФРВ» — фактически независимое исследование времени

- Источник: **другая модель** `state.frvStudy.cycles[].observations[]`, не `state.steps[].frv`.
- Паспорт с 8 полями: ID исследования/процесса/операции, статус, оператор, наблюдатель, место, такт.
- Каждый цикл содержит таблицу **19 колонок** (включая номер и удаление): фактическое и нормализованное действие, время, способ, ценность, тип потерь, причина, ключевые моменты, качество/безопасность, инструмент/материал, маршрут, расстояние, доказательство, кандидат в стандарт.
- Шесть дашборд-показателей, классификаторы `VA / NVA_Necessary / NVA_Waste / WAIT / BREAK / OTHER`, 13 кодов потерь, 6 режимов выполнения.
- Кнопки: **«Построить ФРВ из описания»**, **«Анализировать ФРВ»**, **«Проверить ФРВ»**, «Добавить цикл», подсказка ИИ по каждой строке, **«Сформировать СОК-кандидат»**, **«Передать подтверждённые шаги в СОП»**.
- Данные сохраняются в черновике/библиотеке и экспортируются моделью `frvStudyExport()` в JSON; основной XLSX получает ФРВ из `state.steps` и **не использует** `state.frvStudy`.

## 3. Что оставить

- Сохранение точных RAW действий и фактически измеренных секунд; ИИ не должен их перезаписывать.
- Сохранение черновика, исходных наблюдений и подтверждений пользователя; ссылки на наблюдения в рекомендации.
- Необязательное измерение нескольких реальных циклов и сравнение их длительности.
- Текущую работающую форму Excel и генерацию СОП/TWI — не перестраивать для упрощения аналитики.

## 4. Рекомендуемая целевая структура

**Один пользовательский пункт «ФРВ» с двумя режимами: «Наблюдения» и «Анализ»**, без нового крупного раздела, дублей и дополнительных рабочих панелей.

### Режим «Наблюдения»

По умолчанию 5–6 понятных полей:
1. Действие (фактически наблюдаемое).
2. Время, сек.
3. Тип времени: ВДЦ / М2 (необходимое без добавления ценности) / М1 (потеря) / ожидание / регламентированный перерыв / неопределённое; **одно взаимоисключающее значение** на однородный интервал.
4. Комментарий/почему возникла потеря (необязательно).
5. Перемещение, м (необязательно).
6. Номер фактически измеренного цикла (необязательно, в расширенном режиме).

Паспорт подтягивает уже известные названия из СОП; независимая ФРВ может вводиться отдельно, без обязательного создания шагов СОП. Не создавать фиктивные замеры из текста ИИ — только черновые предложения с явной маркировкой.

### Режим «Анализ»

Сначала без ИИ детерминированно показывать:
- Общее замеренное время, время ВДЦ/М2/М1, ожидание/перерыв отдельно; доли в % с явным правилом учета.
- Самые затратные действия, места потерь и длительности; предупреждения о пропущенных и противоречивых измерениях.
- При нескольких циклах — сравнение, среднее/разброс только по фактически измеренным циклам.

**Одна необязательная кнопка «Предложить улучшения с ИИ»**: 3–5 проверяемых предложений «потеря → причина (если подтверждена) → мера → ориентировочный эффект». Не утверждать нормативное/стандартное время и не подменять фактический замер оценкой модели.

Никаких обязательных СОК-кандидатов, отправки шагов в СОП, 8 статусов или ИИ-подсказок по 19 колонкам в основном сценарии. Расширенные поля можно хранить и открывать по запросу через «Дополнительно», сохраняя API/черновики и возможность полной инженерной экспертизы.

## 5. План реализации **только после отдельной команды**

**Крупный пакет, без дробления на микроэтапы**:
1. Исправить арифметику/единицы времени, взаимную исключаемость классификации, пропуски замеров и контроль устаревания анализа. Для существующих данных предусмотреть явное предупреждение при неоднозначной разметке; не терять RAW и секунды.
2. Перестроить только видимый UX: единая точка входа «ФРВ», компактная таблица наблюдений, анализ как итоги на основе них; необязательные циклы и «Дополнительно». Не создавать новую параллельную сущность и не ухудшать Excel.
3. Убрать из обычного интерфейса СОК-кандидат и передачу в СОП, сделать защиту от случайной перезаписи независимо от скрытия кнопки.
4. Сократить контекст и ответственность ИИ до безопасного описания потерь и предложений, сохранять запрос/ответ/согласие, никогда не изменять измеренные RAW и время.
5. Регрессировать: отсутствие потерь/дублей данных при сохранении черновика, действующий XLSX Stage32.2 с фотографиями, импорт, СОП, TWI, настройки Yandex, не добавлять обязательной связки ФРВ→СОП→TWI.

**Приёмка:** пользователь за 1 проход может ввести 5–10 действий с длительностями, увидеть корректные доли времени и 3 проверяемых улучшения без заполнения большого паспорта или кандидатов в стандарт. Пустые времена не считаются нулями; категории не удваивают длительность; старый СОП не перезаписывается. Результат можно сохранить без обращения к ИИ.
