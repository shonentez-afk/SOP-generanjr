# Единый план: ФРВ и «Анализ ФРВ» → исследование → улучшение → проект СОП

**Консолидированный план на 20.11.2026, основанный на подтверждённых ограничениях пользователя. Детали будущей Stage34 — предложения к реализации, ещё не принятый релиз.** Это единый план, а не реализованная Stage34. Сведены уточнения пользователя, аудит ФРВ и текущая Stage33. Он заменяет предыдущие предварительные планы автоматизации; старые отчёты остаются историей. Изменений исполняемого кода в рамках подготовки этого плана нет.

## 1. Цель и ограничения

Создать удобный инструмент для инженера/наблюдателя, который прямо на ПК вводит замеры реальной работы, автоматически получает количественный анализ времени и потерь, по желанию запрашивает рекомендации текстового ИИ, подтверждает будущую последовательность и создаёт из неё **новый проект СОП**. При этом первоначальное исследование, исходные замеры и существующий СОП сохраняются независимо друг от друга.

**Неподлежащие изменению решения:**
- На заводе не ведут ФРВ в Excel. **Никакого импорта чужих XLSX/CSV, вставки внешних таблиц и обязательных внешних источников замеров.** Excel — только исходящий отчёт/резервная копия.
- Программа работает на настольном ПК. **Не нужны кнопочный секундомер, видеоанализ, запись видео, функции аудио/OCR.** Текущая модель ИИ не поддерживает видео; провайдер/прокси ради этого не менять.
- Фактические действия и времена вводятся человеком в приложении. **ИИ не создаёт реальные замеры, не подменяет секунды, не устанавливает нормативы автоматически и не утверждает СОП за человека.**
- Два разных сценария: (А) «Редактор СОП → ФРВ» — время по готовящимся шагам СОП и лист XLSX; (Б) независимый «Анализ ФРВ → новый проект СОП». **Не объединять вкладки** и не делать путь Б обязательным.
- TWI остаётся **только производным из СОП**, по отдельной команде. Не формировать обязательную цепочку ФРВ→СОП→TWI.
- Сохраняются Yandex Cloud-прокси, настройки моделей, выключенный `SOP_ENABLE_MODEL_ROUTING`, локальная ExcelJS 4.4.0, локальные ISO-пиктограммы, фоторедактор Stage31, исправленный экспорт фотографий Stage32.2, архив/черновики/импорт СОП и настольный `file://` режим.

## 3. Два независимых сценария продукта

### Сценарий A — «Редактор СОП → ФРВ»
1. Пользователь создаёт/редактирует СОП и его действия.
2. По желанию классифицирует затраты и дополняет сведения ФРВ.
3. Получает в привычном Excel-листе время/ВДЦ/М1/М2 и остальное.
4. Проверяется, что классифицированные интервалы не превышают общую длительность, не возникает двойного учёта; единицы времени подписаны корректно.
5. Это **не требуется для начала «Анализа ФРВ»**.

### Сценарий Б — «Анализ ФРВ → оптимизация → проект СОП»
1. Создать или открыть отдельное исследование ФРВ.
2. Описать исследуемую операцию и вручную вводить **фактически наблюдаемые действия и времена в секундах**.
3. Добавить реальные повторные циклы; быстро переносить названия действий без копирования секунд как будто это новый замер.
4. Программа немедленно рассчитывает распределение времени, потери, стабильность процесса и полноту данных.
5. По желанию текстовый ИИ предлагает типы затрат, причины и конкретные улучшения; пользователь утверждает/отклоняет.
6. Пользователь выбирает подходящие действия и утверждает последовательность/ключевые моменты/проектное время. Без ИИ тоже можно.
7. По отдельному подтверждению создаётся новый проект СОП, с сохранением старого документа и возможности восстановления; TWI только потом и отдельно.
8. На любом шаге исследование сохраняется локально, может быть открыто позже, а внешняя копия выгружается в XLSX и/или JSON.

## 4. Пользовательский интерфейс — без лишних экранов

**Не создавать новый раздел поверх «Анализа ФРВ».** Доработать единственную уже существующую вкладку Stage33 в четырёх логических последовательных зонах:

**Верхняя строка управления исследованием:**
- `Новое исследование` — имя/операция (обязательно), участок/исполнитель/наблюдатель/дата (необязательные).
- `Открыть` — компактная библиотека исследований с поиском, датой последнего изменения, статусом и числом замеренных циклов.
- Виден индикатор `Изменено` / `Сохранение…` / `Сохранено` / `Не удалось сохранить`; факт успешной записи показывать только после подтверждения хранилищем.
- `Сохранить в Excel` — понятный пользователю отчёт. В одном небольшом меню резервных копий — `Сохранить JSON` / `Восстановить JSON`. Не дублировать действия множеством кнопок.

**Зона 1 — Наблюдения:** одна компактная таблица, основные поля `Действие · Время, сек · Тип времени · Комментарий · Перемещение`, плюс выбор `В СОП`. Кнопка `Добавить действие`, необязательная `Повторный цикл`. Все специальные сведения (инструмент, качество, безопасность, причина потери, доказательство, маршрут и др.) по `Подробнее` в нужной строке. Отдельный черновик предложенных ИИ действий; без реального времени они не попадают в измеренные итоги.

**Зона 2 — Анализ:** сразу локально рассчитанные показатели, предупреждения о неполных данных, Парето, топ действий по времени/потерям, сравнение реально повторенных циклов. Не прятать базовые расчёты за кнопкой ИИ. Одно необязательное действие `Предложить улучшения с ИИ`.

**Зона 3 — Подготовка будущего СОП:** отметить необходимые действия, проверить улучшенную последовательность, проектное время, ключевые моменты, безопасность. `Подготовить проект СОП` → предпросмотр → `Создать новый СОП`. Не менять исходный документ без резервирования и отдельного подтверждения.

## 5. Модель данных и надёжное хранение (главный приоритет Stage34)

- Исследование — отдельная сущность: `studyId`, название операции, место/исполнитель/наблюдатель, даты создания/изменения, статус, версия схемы, набор циклов, анализ, решения и предложения. У **каждого** цикла и наблюдения постоянный идентификатор. Не смешивать исследования с `state.steps` текущего СОП.
- В строке хранить **RAW действие**, `durationSec` (измеренные секунды или **null**, но не ложный 0), классификацию, комментарий/маршрут, подтверждённые выводы и изменения ИИ отдельно. Исправление измерения не уничтожает сведения о его первоначальном происхождении.
- Предпочтительно использовать отдельное хранилище IndexedDB с транзакционной записью; не держать единственным местом хранения большой JSON в общих черновиках СОП. Дебаунс автосохранения, сохранение при переключении исследования, проверка завершения транзакции, предупреждение при сбое и возможность повторной записи. Не считать закрытие окна гарантией завершения записи.
- Библиотека: создать, сохранить, продолжить, сделать копию, архивировать/удалить с подтверждением. **Не терять исследование при создании СОП**. Не перезаписывать одно исследование другим; при необходимости проверять версию при открытии в двух окнах.
- Отдельные снимки перед разрушительными действиями; восстановление из последней успешной копии. Продумать перенос текущего Stage33-черновика в самостоятельную библиотеку **без потери данных** при обновлении кандидата.
- Для запуска через `file://` хранение привязано к конкретному браузеру/профилю и может зависеть от пути/политик браузера. Смена браузера, очистка данных и разные ПК не должны считаться безопасной передачей; поэтому нужен самостоятельный внешний резерв.

## 6. Экспорт/восстановление: Excel — на выходе

### Отдельный XLSX «Исследование ФРВ»
Формируется локально через уже встроенную ExcelJS; не меняет существующий XLSX готового СОП.

- Лист **«Наблюдения»**: паспорт исследования, дата, операции и цикл, порядок, действия RAW, время в секундах, категория, перемещение, комментарий, признак замера/пропуска. Исходные времена без округления в исходных данных.
- Лист **«Анализ»**: суммы ВДЦ/М1/М2/ожиданий/перерывов, проценты с указанным знаменателем, неполные замеры, статистика только по сравнимым фактически измеренным циклам, топ потерь/Парето, пометки о незакрытых классификациях. Для печати понятная ширина колонок и формат времени.
- Лист **«Улучшения»**: предложение, проблема/источник (ID наблюдения), решение пользователя (подтверждено/отклонено/не рассмотрено), ожидаемый **прогнозный** эффект отдельно от **реально подтверждённого** эффекта. Если предложений нет — пустая структурированная таблица.
- Имя файла с операцией и датой, версия выгрузки и ID исследования; при повторной выгрузке не менять измеренные данные. При ошибке скачивания показать сообщение. Никаких внешних сетевых библиотек и серверного XLSX.

### JSON — точная переносимая резервная копия
- Сохранять **все** исходные данные (включая ID, циклы, текст описания, источник ИИ, человеческие подтверждения, метаданные, предложения, связи со шагами СОП и версию схемы).
- Дать кнопку `Восстановить копию JSON`: проверка схемы/версии/ID/числовых значений, предпросмотр объёма и исследования, выбор `Создать отдельное исследование` по умолчанию. Никогда не перезаписывать текущее исследование молча.
- Excel нужен как **читаемый отчёт и внешняя копия**; JSON — как **полное техническое восстановление**. XLSX не объявлять обратимо импортируемым форматом.
- Не обещать запись файлов в произвольную папку ПК без разрешения браузера. Пользователь выбирает место сохранения через стандартное скачивание; полезно напоминать о регулярной внешней копии перед завершением работы.

## 7. Детерминированная аналитика, которую делает программа, а не ИИ

1. **Контроль исходных данных:** положительная длительность или `null`; отрицательные значения запрещены; отсутствующие замеры и неклассифицированное время видны отдельно. Не включать неизвестные времена как реальные 0 сек.
2. **Категории:** ВДЦ, М2, М1, ожидание, перерыв, «не определено» — **взаимоисключающие для каждого однородного интервала**. Ожидание и перерыв не должны второй раз суммироваться как М1 без явно выбранного правила отображения. Указать, входят ли перерывы в знаменатель конкретного процента.
3. **Анализ потерь:** группировать подтверждённые потери по видам/причинам, сортировать по секундам, строить Парето с долями и накопленным процентом, показывать крупнейшие потери и типы деятельности.
4. **Повторные циклы:** совпадающие названия/порядок подбирать как **кандидатов на сопоставление**, а не автоматически склеивать разные операции; пользователь подтверждает соответствие. Считать среднее/медиану/минимум/максимум/разброс (CV), предупреждать о нетипичных циклах; не смешивать разные условия/варианты без согласия.
5. **Сравнение «до/после»:** только два **реальных, подписанных** набора замеров с понятными условиями, размером выборки и сопоставимыми границами операции. Показывать разницу в секундах и процентах, не подменять прогноз ИИ фактическим улучшением.
6. **Результат для инженера:** сколько секунд занимает операция, сколько добавляет ценность, где измеренные потери, какие действия нестабильны, какие решения требуют проверки. Краткая сводка без сложных расчётных настроек.

## 8. Текстовый ИИ — помощь в классификации и улучшениях

- ИИ уже может предложить **черновой список действий** по описанию. Время таких строк всегда `null` до фактического замера.
- Следующий пакет: **массовая необязательная классификация** существующих действий `ВДЦ / М2 / М1 / ожидание / перерыв`, предполагаемые виды потерь и причины, обоснование предложения и уровень уверенности/пометка `требует проверки`. Не применять предложение автоматически; особенно спорные причины должны оставаться гипотезами.
- Отдельно вывести **3–5 приоритетных рекомендаций**, связанных с конкретными подтверждёнными наблюдениями: `проблема → доказательство → предположенная причина → предлагаемая мера → ожидаемый эффект (оценка) → статус решения инженера`.
- Пользователь может принять/отклонить каждую рекомендацию или массово подтвердить только предварительно просмотренные классификации. Исходные RAW действия и секунды **никогда не меняются ИИ**.
- Если пользователь меняет наблюдение, связанные рекомендации/анализ отмечаются **устаревшими** до повторной проверки. В офлайн-режиме весь количественный анализ и подготовка СОП продолжают работать без облака.
- Все сетевые вызовы через **существующий Yandex-прокси**, модели/ключи/URL не трогать, `SOP_ENABLE_MODEL_ROUTING` остаётся выключенным.

## 9. Подготовка СОП на основе исследования

- Из фактов и утверждённых решений собрать **проект будущего процесса**, не копировать все зафиксированные ожидания/потери автоматически в СОП. Однако обязательные ожидания, проверки и операции можно включить инженерным решением.
- Подтверждённые шаги, порядок и ключевые моменты — редактируемые; опасности/СИЗ/качество должны быть проверены человеком. ИИ может предложить формулировки, но не выдумывать меры безопасности.
- Время из измерений — **описательная статистика**, не автоматически нормативное время. Проектное время пользователь выбирает/редактирует отдельно; сохраняются все `observationId`, циклы, исходные измерения и решение о проектном времени.
- **Существующий СОП не изменяется без сохранённой резервной копии, предпросмотра и отдельного подтверждения.** После создания нового СОП исследования остаются доступными в библиотеке. TWI отдельно из итогового СОП; никакого автоматического запуска TWI.

### Stage34 — ЕДИНЫЙ БОЛЬШОЙ пакет автоматизации и сохранности ФРВ

В отдельной ветке от принятой Stage33, без дробления на множество мелких PR:

1. **Изолированная библиотека исследований и надёжное автосохранение:** ID, список/поиск/открытие/копирование, контроль подтверждённой записи, аварийное восстановление, независимость от текущего СОП.
2. **Удобство ввода и циклы:** компактная таблица, быстрый повтор списка действий **без копирования измеренного времени**, редактирование/подтверждение соответствий циклов, сохранение RAW и источников, проверка пропусков.
3. **Детерминированный полноценный отчёт:** категории без двойного учёта, доли/Парето/топ потерь, сравнение фактических циклов, явные ограничения статистики и реальные «до/после» при наличии замеров.
4. **Необязательные подсказки текстового ИИ:** массовая классификация и конкретные рекомендации, объяснение/уверенность/согласование; гарантии неизменности RAW и секунд.
5. **Экспорт отчёта XLSX и полное резервирование JSON:** листы «Наблюдения»/«Анализ»/«Улучшения», проверенное восстановление JSON отдельным исследованием, предсказуемое поведение при отказе диска/хранилища.
6. **Сквозная безопасность передачи в СОП:** подготовка и подтверждение улучшенного процесса, неизменность исходного исследования и прежнего СОП, сохранение источников в новом документе.
7. **Всё протестировать одним набором** до показа пользователю: Linux/Windows, реальный Excel и отсутствие регрессий СОП, TWI, ExcelJS, фото Stage32.2, библиотеки и AI.

### Что отложить до появления реальной потребности

- Сложные экспертные расчётные методы, требующие дополнительных датчиков или нормативных баз.
- Совместная облачная работа и автоматическая запись в корпоративную папку без проверенного разрешённого механизма.
- Дополнительные большие разделы/конструкторы анализа; сначала оценить удобство единой вкладки.
- Кнопочный хронометраж, видео и импорт сторонних Excel-замеров — **исключены**, не «отложены на потом».

## 11. Критерии приёмки Stage34 (конкретные испытания)

1. **Три независимых исследования** с разными операциями: создание, заполнение, переключение, закрытие браузера, повторное открытие; отсутствие перепутанных действий и времени.
2. При вводе нескольких десятков строк видно реальное состояние автосохранения; отказ IndexedDB/нехватка места показывается явно, ничего не объявляется «сохранено» ложно; есть внешний экспорт.
3. Повторный цикл добавляется с теми же названиями действий, но **пустыми временами**; новый фактический замер вводится отдельно. `null` не равен `0`; нет отрицательных и задвоенных секунд.
4. Правильно проверяются ВДЦ/М1/М2/ожидания/перерывы; суммы сходятся с измеренными интервалами, проценты объяснимы. Парето строится только по подтверждённым потерям.
5. ИИ предлагает классификацию/улучшения, но **RAW-действия и измеренные секунды побайтово неизменны**; отсутствие сети не мешает всему остальному.
6. Выгруженный XLSX читается в Microsoft Excel: все реальные циклы, секунды, отсутствующие измерения, сводка, Парето и решения. Файл читается и печатается, не содержит придуманных данных.
7. Экспорт JSON и восстановление в чистом профиле браузера возвращают то же исследование со всеми ID, циклами, решениями; по умолчанию **не затирают другое**.
8. После улучшения исследование формирует новый СОП и сохраняет прослеживаемость; отмена переноса оставляет текущий СОП без изменений, резервная копия позволяет восстановить документ с фотографиями.
9. Полная регрессия принятых модулей: экспорт СОП и Excel-фото Stage32.2, проверка/генерация СОП, TWI из СОП, локальные ISO и модельные настройки/Yandex, работа через `file://`. Стандартное пользование не требует новых сервисов и провайдеров.
10. Отдельная **ручная приёмка на ПК пользователя**; только после неё Stage34 вливается в `main`.
