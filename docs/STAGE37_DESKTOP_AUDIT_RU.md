# Stage37 — комплексный аудит настольного конструктора СОП

**Дата:** 23.11.2026. **Исходная принятая версия:** Stage36.1 в `main` (PR #32 merged, TWI XLSX работает по подтверждению пользователя). **Статус:** новая версия подготовлена в изолированной ветке, не объединять с `main` без проверки на компьютере.

## Реально обнаруженные проблемы и исправления

| Приоритет | Наблюдение по исходному коду Stage36.1 | Решение Stage37 |
|---|---|---|
| P0 | При баннере «Найден несохранённый черновик» `saveDraft()` и `beforeunload` потенциально могли записать текущую пустую сессию поверх ещё не восстановленного черновика | Блокировка автоперезаписи, пока не выбран «Восстановить» или подтверждён отказ. Для повреждённого черновика — скачать исходный текст, затем только с подтверждением удалить |
| P0 | Открытие другого СОП в библиотеке `docOpen()` загружало его в текущий редактор без проверки несохранённых шагов и ручных TWI-правок | Сравнение текущего снимка СОП с сохранённой версией; при отличии диалог «ОК — перейти / Отмена — сохранить» |
| P1 | «Новый документ» проверял только наличие шагов и описания, а название операции и TWI без шагов могли быть потеряны без предупреждения | Дополнительная проверка метаданных и TWI при создании нового СОП; предыдущее подтверждение для непустых шагов сохранено |
| P2 | HTML называл Wikimedia источником пиктограмм и предупреждал о возможной потере картинок без сети — это противоречило фактическому локальному комплекту ISO 7010 | Текст заменён на корректное объяснение встроенного локального набора |
| P2 | В интерфейсе не было явной отметки версии: легко открыть устаревший HTML из папки Downloads и ожидать функцию TWI XLSX | Рядом с названием добавлена нейтральная пометка Stage37 (проверка) |

Все исправления реализованы **одним дополнительным** модулем `src/modules/documents/stage37-data-loss-safety.js` и точечным изменением HTML-шаблона. Исходные 64 модуля принятой Stage36.1 не изменены. Модель ИИ, прокси Yandex, FRV, генерация TWI, фото, экспорт СОП/TWI XLSX и ExcelJS/ISO остаются прежними.

## Что НЕ подтверждено автоматическими тестами

- Сложная работа корпоративной сетевой папки с двумя реальными ПК и разрешениями Windows/Chrome.
- Физическая распечатка на конкретном принтере и соответствие местным фирменным бланкам (тестируются структура XLSX, A4 и параметры страниц).
- Реальные производственные ответы Yandex AI и нормативная правильность создаваемых текстов (тестируется API/UX-обработка и контроль применения, но без производственных ключей и фактической экспертной оценки).
- Работа и эргономика на телефоне — мобильная версия в постановку задачи не входит.
- Абсолютная гарантия сохранности пользовательских данных; продолжайте делать переносимые JSON-копии.
