# Безопасная модернизация первой Yandex Cloud Function

Адрес рабочего прокси в Stage 26: `https://functions.yandexcloud.net/d4ehdpoue3sve6s0f92b`.

Этот PR **не меняет** HTML, URL, конфигурацию, модели и промпты Конструктора СОП. Код `proxy/index.py` предназначен в первую очередь **для новой тестовой Cloud Function**, а не для немедленной замены рабочего экземпляра. Точка входа: `index.handler`, Python 3.11+.

## По умолчанию (все SOP_* флаги выключены)

- Старый endpoint `https://llm.api.cloud.yandex.net/foundationModels/v1/completion`, прежний `Api-Key` и `YC_FOLDER_ID`.
- Модель всегда `gpt://<folder>/yandexgpt-lite/latest`, даже если клиент передал другое имя.
- `maxTokens` всегда строка `"2000"`.
- Ответ строго `{"choices":[{"message":{"content":"..."}}]}`.
- Никаких скрытых повторов, автопереключений, новых внешних запросов.
- Добавлены ограничение размера тела, обработка JSON/base64, безопасные ошибки и редактирование секретов.

## Опциональные флаги — все по умолчанию выключены

| Переменная | Назначение |
|---|---|
| `SOP_ENABLE_MODEL_ROUTING=1` | Разрешить белый список имён моделей |
| `SOP_ENABLE_CLIENT_MAX_TOKENS=1` | Учитывать `max_tokens` клиента |
| `SOP_MAX_OUTPUT_TOKENS=4000` | Верхний предел; действителен только вместе с предыдущим флагом |
| `SOP_STRICT_COMPLETION=1` | Отклонять обрезанные или заблокированные моделью ответы |
| `SOP_INCLUDE_USAGE=1` | Добавлять необязательные метаданные usage и status |

Тестовый белый список: `yandexgpt-lite` → `yandexgpt-lite/latest` (старый маршрут, реальная доступность требует проверки); `yandexgpt` → `yandexgpt-5-pro`; `yandexgpt-5` → `yandexgpt-5.1`; `yandexgpt-5.1` → `yandexgpt-5.1`. Конструктор не получает права передавать произвольный URI. Подписи моделей в пользовательском интерфейсе пока не меняются.

## Проверка и внедрение

1. Сохраните код и конфигурацию текущей Cloud Function, её версию и переменные окружения. Не публикуйте ключи в GitHub.
2. Создайте отдельную тестовую Yandex Cloud Function. Загрузите в неё `proxy/index.py`, задайте `YC_API_KEY` и `YC_FOLDER_ID`. Новые флаги не включайте.
3. Проверьте на тестовом запросе оригинальный контракт ответа; затем отдельно включайте по одному флагу и проводите реальные тесты `generate_sop`, `review`, `twi_generate`, `frv_study_analyze`, лимитов и ошибок.
4. Для тестов без реальных запросов запустите `python -m unittest discover -s proxy/tests -v`.
5. Не переключайте рабочую функцию на эту реализацию до реальных проверок в вашем каталоге и ручной браузерной регрессии Stage 26.

Ограничения: функция остаётся текстовой, не поддерживает фото/видео, RAG, JSON Schema и безопасную аутентификацию конечного пользователя. CORS не защищает от расходования облачной квоты. Таймаут конструктора 45 секунд, тогда как ожидание upstream в функции 60 секунд.

**Откат**: восстановить сохранённую рабочую версию Yandex Cloud Function. Выключение флагов возвращает прежний выбор модели и лимит токенов, но не полностью отменяет новую обработку ошибок.

В комплекте есть локальные мок-тесты; они не доказывают доступность выбранных URI в реальном Yandex Cloud.
