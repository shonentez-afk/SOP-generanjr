# UX/UI-аудит Stage 13 — Конструктор СОП

**Дата:** 2026-11-18  
**Проверенный релиз:** `releases/stage13-layered-photo-editor.html`, GitHub blob `73588ab491e1e160b041e9ab4f9c51f25470d46f`.  
**Область:** 7 вкладок, интерфейс ПК/планшета/телефона, ФРВ, анализ ФРВ, TWI, чек-лист, редактор шагов и фото, импорт/экспорт XLSX, библиотека, публикация/версионирование, доступность и offline UX.  
**Правило:** ни один исходный файл приложения и ни одна настройка ИИ/прокси в ходе аудита не изменены.

## Важные ограничения методики

- Код релиза, в том числе ключевые обработчики, сверялся непосредственно с GitHub.
- Функциональные проверки выполнены в headless Chromium/Playwright с загрузкой HTML через `set_content`: среда блокирует навигацию на `file://`, `data:` и локальный HTTP. Вместо реальной браузерной IndexedDB использована тестовая имитация с поддержкой операций `get/put/getAll/delete` и транзакций. **Долговременная реальная IndexedDB на ПК пользователя не подтверждена.**
- Для оценки ожидаемого адаптивного макета подставлялась локальная Tailwind CSS из донорского проекта. Это приближение, а не точная сборка стилей Stage 13. Отдельно проверено отображение **без** Tailwind — оно заметно ломается. Прямой сетевой доступ к CDN и ИИ-прокси не проверялся.
- Использованы синтетические данные. Секреты, реальные фото/СОП и обращения к ИИ-сервису не требовались.
- Первичный объединённый негативный тест имел побочный эффект: клавиша Backspace удаляла подпись, поэтому два последующих сравнения фото оказались ложно отрицательными. **Они перепроверены отдельным чистым сценарием:** сохранение старой/новой версии и независимые подписи прошли 7/7 проверок.

## Результат

Критические функции в целом открываются и исполняются, но найдены блокирующие ошибки для передачи проекта между пользователями и надёжного редактирования фото. **Stage 13 нельзя считать полностью принятой по UX/UI и регрессии.**

### P0 — Потеря фото из импортированного XLSX после восстановления черновика

**Воспроизведено:** экспортировать XLSX с фото → очистить тестовую фото-IndexedDB → импортировать этот XLSX → изображение есть на шаге → сохранить черновик → восстановить черновик → изображение исчезает (1 фото до восстановления, 0 после).

**Причина в коде:** `importSopFromXlsx` восстанавливает `imageData` и `imageBuffer`, но не записывает импортированную картинку в `stepPhotos` через `idbPutPhoto`. Черновик намеренно содержит только `hasPhoto`, а `applyDraft` ожидает Blob из IndexedDB. При совпадении номеров шагов с устаревшими фото возможна подмена, это **отдельный риск**, не воспроизведённый в тесте.

**Исправление:** сохранять все импортированные фото в IndexedDB до сообщения об успешном импорте; проверять ошибки записи; тестировать цикл XLSX→импорт→закрытие→восстановление→экспорт.

### P1 — Внешняя Tailwind CSS мешает локальному использованию

**В коде:** `<script src="https://cdn.tailwindcss.com"></script>`, хотя ExcelJS уже встроена локально. **В тесте без Tailwind** выпадают сетки форм, кнопки теряют оформление, некоторые блоки, скрываемые классом `hidden`, показываются. Это противоречит пользовательскому сценарию запуска одного HTML без стабильного интернета.

**Исправление:** встроить проверенную совместимую CSS-сборку в единый HTML, сохранив **без изменений** ИИ-прокси и остальные сетевые сценарии. После сборки визуально сравнить все 7 вкладок.

### P1 — Клавиша Backspace удаляет объект в редакторе фото

**Воспроизведено:** добавить подпись → оставить объект выделенным → поставить курсор в поле подписи → нажать Backspace. Буква не удаляется, исчезает весь объект.

**Причина:** глобальный обработчик `keydown` выполняет `deleteSelected()` при Backspace/Delete и `selected.size>0`, не проверяя, что фокус на `input/textarea/contenteditable`.

**Исправление:** игнорировать горячие клавиши удаления и копирования объектов, когда фокус в поле ввода; добавить клавиатурный регрессионный тест.

### P1 — «Новый документ» блокируется после публикации

**Воспроизведено:** опубликовать СОП → перейти в библиотеку. `docNewBtn.disabled === true`, хотя создание **другого** документа не меняет опубликованную версию. В `applyDocumentLock` кнопка `docNewBtn` прямо включена в `blockedIds`.

**Исправление:** разрешить создать независимый документ из режимов «Опубликован» и «Архив», сохранив запрет изменения содержимого текущей зафиксированной версии. Пересмотреть блокировку чтения истории/резервных копий/проверок: сейчас эти действия тоже попали в `blockedIds`.

### P1 — JSON-выгрузка и сетевая библиотека не переносят изображения

**Подтверждено анализом кода:** `docDownloadJson` экспортирует `docSnapshot` с `hasPhoto` и JSON-разметкой, **без исходного Blob и итогового JPEG**. Синхронизация сетевой папки сохраняет JSON документов; фото остаются в локальной IndexedDB конкретного браузера. На другом ПК такой документ не самодостаточен.

**Статус:** ранее задокументированное ограничение Stage 13, но это серьёзный UX-риск при восприятии команды «Скачать JSON» как полного резервного копирования.

**Исправление:** либо экспортировать переносимый ZIP/пакет с JSON и изображениями, либо явно помечать JSON как «без фотографий» и предусмотреть корректную синхронизацию медиа между ПК. Не менять формат XLSX без тестов.

### P2 — Ложный баннер о блокировке документа

**Воспроизведено в тесте с локальными стилями:** текущий статус `Черновик`, у `#documentLockBanner` класс `hidden`, но `getComputedStyle(...).display === "flex"`, поэтому показывается сообщение «Опубликованный документ защищён…».

**Причина/риск:** правило приложения `.document-lock-banner{display:flex}` конфликтует по приоритетам с utility-классом `hidden`; без Tailwind `hidden` вообще не действует. Проверить на финальной локальной CSS-сборке, что баннер физически скрыт при черновике.

### P2 — Горизонтальная прокрутка вкладки «Редактор» на телефоне

При ширине экрана 390 px `documentElement.scrollWidth === 523` px. Установлена конкретная причина: два поля «Должность» и «ФИО» внутри `#agreedContainer > .flex.gap-2` имеют `flex-1` без `min-w-0` или мобильного переноса. Второй ввод уходит вправо до координаты 523 px. Сами остальные шесть вкладок при 390 px в таком тесте не расширяли страницу.

**Исправление:** на узком экране расположить поля согласующего вертикально, либо ограничить `min-width:0` и задать контролируемую сетку. Повторить проверку на 320, 375, 390, 768 и 1366 px.

### P2 — Очистка TWI без подтверждения

**Воспроизведено:** заполнить «Цель обучения» и «Инструктор» → нажать «Очистить» → оба значения немедленно стерты; `confirm` не вызывался. Данные сразу записываются в черновик, отсутствует Undo.

**Исправление:** подтверждение при непустых полях либо undo/восстановление из временной копии.

### P2 — Доступность клавиатуры / screen reader

В тестовой видимой части редактора **25 из 25** `input/select/textarea` не имеют программной подписи: рядом есть визуальные `<label>`, но нет связей `for/id` и `aria-label`. Семь кнопок вкладок не объявлены как tabs с `aria-selected/aria-controls`. Редактор фото не имеет полноценного `role=dialog`, `aria-modal` и focus trap; сообщения `toast` не имеют `aria-live`.

**Исправление:** семантические подписи, keyboard/focus-тесты, modal-focus, live-region. Первая очередь — основные формы и редактор фото.

### P2/P3 — Сообщения и второстепенный UX

- При последовательных действиях несколько зелёных toast могут перекрывать шапку на мобильном экране; ограничить число сообщений и адаптивную ширину.
- При успешном XLSX-импорте сообщение «Импортировано шагов…» формируется **и внутри** `importSopFromXlsx`, **и снаружи** в `change`-обработчике, то есть возможны два одинаковых уведомления.
- Встроенная кнопка «Запустить проверку» менеджера документов дала **9/9 PASS**, несмотря на выявленную отдельным тестом потерю импортированных фото: добавить интеграционные проверки картинок и восстановления в набор собственных self-tests.

## Рекомендуемый порядок исправления без регрессий

1. **Сохранность данных (обязательный P0):** сохранение фото после импорта XLSX и переносимые резервные копии. Тесты должны проверять данные после перезапуска.
2. **P1 без изменения ИИ:** полностью локальное оформление (Tailwind), исправление клавиши Backspace в редакторе фото, корректная возможность создать новый СОП из опубликованного/архивного.
3. **P2:** адаптивность согласующих, состояние баннера, подтверждение очистки TWI, доступность, сообщения.
4. Сквозная регрессия с реальной Chromium/Edge под Windows по `file://`, с настоящей IndexedDB, сохранением СОП и фото, XLSX, публикацией и версиями, ручной проверкой доступа к сетевой папке.

**Отдельный запрет:** не изменять адрес прокси Yandex Cloud, модели, параметры и маршрутизацию запросов ИИ. Текущее использование сети для ИИ не является дефектом, оно предусмотрено архитектурой. **Этот аудит не изменяет приложение.**
