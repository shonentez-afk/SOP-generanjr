## Действия в существующей карточке шага

- **↑ / ↓:** перемещение шага на одну позицию без создания нового ID. Связанные фотографии, индивидуальные времена/классификация ФРВ, причины, ключевые моменты, комментарии остаются у того же шага; общая длительность пересчитывается прежней функцией.
- **⧉:** дублирование шага сразу после исходного, новый уникальный ID, все тексты и нумерованные причины сохраняются. Оригинальный снимок/разметка копируются в отдельную запись IndexedDB. При невозможности создать копию фото действие отменяется, новый шаг не появляется.
- **▾ / ▸:** сворачивание/разворачивание подробностей отдельного шага. Только отображение: не переписывает SOP, TWI, ФРВ, черновик или JSON. Состояние свёрнутости не сохраняется после перезапуска.
- **↶ Отменить:** отмена последних **20 структурных действий** (добавление, удаление, перемещение, дублирование); сочетание Ctrl+Z работает вне текстового поля во вкладке СОП. Обычная отмена ввода текста браузером не перехватывается. Восстанавливаются прежний порядок и удалённый шаг; **фото удалённого шага остаётся в IDB**, поэтому отмена безопасна.
- **🗑:** прежняя кнопка удаления на этом этапе перехватывается новым модулем **до** старого обработчика, удаляющего IndexedDB-файл; пользователю сообщается о возможности отмены.

## Ограничения и защита данных

1. Отмена действует только в рамках **текущей открытой сессии/документа**. Внешняя замена массива шагов, другой документ, генерация/импорт шагов сбрасывают недействительную историю; восстановление после перезапуска ПК выполняется обычным механизмом черновика/библиотеки/резервной копии, а не кнопкой отмены.
2. Поскольку фото удалённых шагов нельзя безопасно удалять до окончания истории, в IndexedDB могут оставаться невостребованные базовые изображения. **Не чистить вручную IndexedDB и не удалять фото при исключении шага**, пока не разработана проверяемая сборка мусора с учётом истории/версий документов.
3. **ФРВ при дублировании:** исходные фактические измерения / `frvSource` не копируются в новый шаг (чтобы не выдавать один замер за два). Расчётная длительность операции копируется, а классификацию времени для нового шага требуется подтвердить заново.
4. TWI из СОП не обновляется автоматически: прежний индикатор устаревшего TWI сообщит об изменении источника. Ручной текст TWI сохраняется.
5. Опубликованные/архивные СОП не допускают структурных действий; сворачивание допускается, т.к. только меняет вид. Стандартная защита Stage37 черновиков сохраняется.
6. Исходные 66 модулей Stage38 остаются **побайтово неизменными**; добавляется единственный `src/modules/editor/stage39-step-actions.js` (67 модулей). Сборщик проверяет, что после удаления добавленного текста итоговый Stage39 HTML **в точности совпадает** с проверенной Stage38 сборкой: Yandex proxy, ExcelJS, ISO, фотографии, корпоративные XLSX, ФРВ, TWI, чек-лист не меняются.

## Реализация и испытания

- `src/app/stage39-parts.json` — новая сборочная конфигурация.
- `tools/build_stage39.py` — автономная HTML-сборка, строгая проверка идентичности Stage38.
- `tests/test_stage39.py` — модульные проверки порядка, неизменности источников, защиты фото и синтаксиса Node.
- `qa/stage39_step_management_browser.py` — настоящий Chrome `file://`: перемещение и Ctrl+Z; сворачивание без изменения данных; независимое копирование исходной фотографии и разметки; защита фактических ФРВ; удаление и отмена без потери фото; сохранение правок других шагов; сброс старой истории; блокировка опубликованных документов; регрессия прежних вкладок.
- `.github/workflows/stage39.yml` — Linux и Windows, публикация кандидата только после успешного тестирования на обеих платформах.
- Выходной HTML: `releases/stage39-step-management-browser-candidate.html`. **До CI PASS и пользовательской проверки не объявлять сборку принятой.**

## Проверка пользователем

В Chrome/Edge открывать Stage39 из отдельной ветки. Проверить перемещение, дублирование (особенно с реальным размеченным фото), сворачивание, удаление с нажатием «Отменить», сохранение/повторное открытие черновика и печать СОП/TWI XLSX. Перед заменой локального HTML сохранить резервную копию библиотеки. В `main` оставлять принятую Stage38 до явного подтверждения.
