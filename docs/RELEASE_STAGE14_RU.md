# Stage 14 — исправления UX/UI для ПК и сохранности данных

Дата: 2026-11-18. Основание: `docs/UX_UI_AUDIT_STAGE13_RU.md` и Issue #4.
Готовый запускной файл: `releases/stage14-desktop-ux-data-integrity.html`.
Базовая версия: `releases/stage13-layered-photo-editor.html` — **сохранена без изменений**.

## Что исправлено (телефон исключён по прямому решению пользователя)

1. **P0, импорт XLSX и фото:** все импортированные фото перед отображением СОП сохраняются в IndexedDB как Blob, читаются обратно для контроля, и только после успешной записи заменяется документ в редакторе. При ошибке импорта записанные фото откатываются, пользователь получает ошибку.
2. **P0, защита библиотеки:** кнопка «Не восстанавливать черновик» больше не очищает всю IndexedDB с фото ранее сохранённых СОП и их версий.
3. **P1, офлайн оформление:** Tailwind CSS 4.1.10 собрана локально и встроена в единственный HTML; внешний `cdn.tailwindcss.com` удалён. *ExcelJS 4.4.0 остаётся встроенной, неизменённой*. Интернет всё ещё может требоваться ИИ через исходный прокси и внешним SVG-пиктограммам.
4. **P1, Backspace:** в редакторе иллюстраций горячие клавиши удаления/копирования объекта не перехватывают Backspace/Delete/Ctrl+D в текстовых полях.
5. **P1, опубликованная версия:** из опубликованного или архивного СОП теперь можно создать **другой** чистый СОП; функции просмотра истории, проверки библиотеки и настройки папки не заблокированы. Редактирование самой опубликованной версии по-прежнему запрещено.
6. **P1, переносимые копии:** «⬇ JSON с фото» сохраняет полный документ, оригиналы фотографий, объединённые JPEG и редактируемые JSON-пометки. Добавлена кнопка «⬆ Восстановить JSON» с защитой от перезаписи существующего ID (создаёт отдельный черновик). Сетевая синхронизация также сохраняет и читает изображения в JSON `schemaVersion:2`, включая контроль целостности нового содержимого.
7. **P2, баннер:** скрыл ошибочно показывавшееся предупреждение о блокировке в состоянии «Черновик».
8. **P2, TWI:** очистка непустой формы требует подтверждения.
9. **P2, доступность:** ARIA-роли вкладок, клавиатурные стрелки/Home/End, подписи полей, роль диалога, удержание фокуса в фоторедакторе и возврат фокуса после закрытия.
10. **P2, уведомления:** устранено дублирование уведомления импорта XLSX, ограничены повторные/одновременные уведомления; добавлены `aria-live`.
11. Усилен встроенный self-test: чтение/запись оригинала фото, JSON-разметки и изолированного ключа версии документа.
12. **Дополнительно:** устранена ошибка `ReferenceError: manual is not defined` при синхронизации папки. Из активной синхронизации исключены скрытые резервные копии и журнал.

## Принципиальные ограничения и совместимость

- **ИИ и прокси не менялись.** Оригинальные URL прокси, модельные настройки, промпты и маршрутизация запросов должны совпадать с Stage 13 побайтно; автоматические регрессионные тесты проверяют блок конфигурации.
- Никаких изменений в мобильной вёрстке, форме согласования на телефоне и общих responsive-правилах специально не делалось. Указанное пользователем переполнение на 390 px оставлено без исправления.
- Известные старые JSON (`schemaVersion:1`), в которые **не включали сами изображения**, не могут восстановить отсутствующие на другом компьютере бинарные файлы. Новые полные JSON (`schemaVersion:2`) содержат фото. Сохранить исходник, которого уже физически нет, невозможно.
- Фотографии могут значительно увеличить размер JSON в сетевой папке; не хранить производственные данные в GitHub.
- Локальные ключи/версия IndexedDB и схема черновика сохранены; формат XLSX не изменён.
- Межверсионная изоляция изображений остаётся прежней.
- Не утверждать, что платформа полностью офлайн: только CSS/ExcelJS и редактор работают без внешнего CDN; ИИ всё ещё использует пользовательский прокси.

Проверены старт/офлайн CSS, 7 вкладок, ввод шага, экспорт XLSX, изображение в IndexedDB, редактор и Backspace, импорт XLSX + восстановление черновика, формирование полного JSON, сохранение/публикация/создание нового СОП, TWI и ошибки JavaScript.
- Второй сквозной сценарий в двух чистых браузерных вкладках с тестовой папкой: экспорт JSON → импорт в пустой профиль и синхронизация JSON из папки → фото восстановлено: **PASS**.

- Долговременная IndexedDB браузера пользователя, реальный сетевой диск и прямой запуск `file://` под Windows требуют ручной проверки: в тестовой среде `Page.goto(file://...)` возвращает `ERR_BLOCKED_BY_ADMINISTRATOR`, тесты использовали имитацию хранилищ.
- Внешний ИИ-запрос **не отправлялся**, конфигурация сохранена и проверяется сравнениями.

## Рекомендуемая ручная приёмка в Windows Chrome/Edge

1. Открыть Stage 14 двойным щелчком, отключить Интернет, убедиться, что все семь вкладок оформлены и работают.
2. Импортировать XLSX с фото, восстановить черновик после закрытия и повторного запуска.
3. Сохранить полный JSON, импортировать его на другом компьютере/профиле: проверить оригинал и редактируемые пометки.
4. Опубликовать СОП, создать новый СОП, открыть старую версию и проверить сохранённые фотографии.
5. Если используется сетевая папка — проверить синхронизацию **на настоящих двух ПК** и разрешения доступа; не использовать сразу производственные файлы.
