## Дополнение по замечанию пользователя: качество TWI Reason Why

В этой же Stage39.1 исправлено поведение по примеру шага «Проверить работу на холостом ходу».

- **Важно:** Key Point отвечает «КАК», причина — «ПОЧЕМУ»; не считать пересказ КМ или добавление фразы «для обеспечения качества/безопасности» достаточной причиной. Это правило усилено в отдельной версионной копии исходных TWI/JI промптов `src/modules/ai/stage39-1-base-prompts.js` (вместо `stage38-base-prompts.js`), ИИ-наставнике, подсказках ✨ и ИИ ФРВ.
- **Запрещено придумывать причины:** «перегрев», «травма», «снижение точности», «поломка» и другие конкретные последствия без исходных сведений; для непонятной выдержки 1 минуты спрашивать технолога, не подбирать объяснение автоматически.
- **Сквозной контроль `stage391TwiReasonQualityIssues`:** проверяет буквальный пересказ Key Point / Action, отдельные пустые общие утверждения и появление неподтверждённых конкретных последствий. При отдельной ИИ-правке причина с явным дефектом **не записывается**, исходный текст остаётся. Для **пользовательских** причин и сгенерированного полного СОП это **мягкое предупреждение** в полной проверке и `openQuestions`, без автоматического изменения, удаления или исправления исходного текста.
- Технические ограничения прежние: одно поле `steps[].reason`, общая либо нумерованные причины, существующие нормативы/параметры и время, исходные ФРВ/фото, корпоративный XLSX и экспорт TWI не менялись.
- `qa/stage39_1_twi_why_browser.py`: воспроизводит три неудачные причины со скриншота, проверяет, что ИИ-правка отвергается, корректная короткая причинная связь принимается, подтверждённый в описании перегрев допускается, полная генерация не теряет шаги и передаёт вопрос инженеру, ручной СОП не меняется, одна общая причина для нескольких КМ допустима.
- Реальные ответы YandexGPT не подтверждены автоматическими тестами: они используют имитацию. Семантическая эвристика намеренно не претендует на инженерную экспертизу и не должна удалять тексты пользователя.

# Stage39.1 — согласование ИИ, причин Stage38 и Анализа ФРВ

Дата: 23.11.2026. База — принятая Stage39 в main; работа ведётся в отдельной ветке feature/stage39-1-ai-reasons-frv-20261123, Draft PR #36. Не объединять с main до Linux/Windows PASS и приёмки пользователем.

## Что исправлено

1. ИИ-подсказки Key Point теперь получают выбранный КМ, все другие КМ, Action и Reasons текущего шага. Применяется только выбранное поле. Ответ с неподтверждёнными числовыми параметрами отклоняется до записи.
2. ИИ-подсказки Reasons сохраняют одно поле steps[].reason: общая причина без номера допустима, разные причины записываются через переносы строк 1., 2., 3. Нельзя незаметно слить уже нумерованные причины, удалить номер или добавить не подтверждённый числовой параметр. Изменение структуры — вручную после проверки инженером.
3. Аналогичный контроль чисел применяется к Action и исправлениям полного ИИ-наставника. В Stage27 все выбранные изменения проверяются до первой записи; подтверждённый человеком ответ может служить источником нового числового факта. Невалидная правка блокирует весь пакет.
4. Промпт единой проверки прямо объясняет правила Stage38, допускает одну общую причину для нескольких КМ и не требует ГОСТ/приказ для каждого Reason. Локальный stage38ReasonIssues сохранён.
5. Пункт 7 чек-листа оценивает наличие Reasons для реально выделенных Key Points, а не слова ГОСТ/Приказ/ISO. Если КМ не требуется, отсутствие Reasons не штрафуется. Автоматическая проверка не подтверждает семантическую истинность причины.
6. В отдельном Анализе ФРВ поле «Почему важно» стало многострочным; в редакторе проекта СОП появилось многострочное поле причин. Сохраняются нумерация и переносы при переносе ФРВ → СОП. Нумерация проверяется перед переносом. ИИ-подсказка строки ФРВ и полный ИИ-анализ отбрасывают вымышленные числовые значения до применения. Исходные измерения RAW, время, frvSource, архивы и расчёты не меняются.
