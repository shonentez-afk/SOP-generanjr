# Stage36 — сохранность библиотеки СОП и самостоятельных исследований ФРВ

Дата начала: 23.11.2026. База: принятая Stage35 в main (PR #30 merged, 96/96 тестов, Linux/Windows PASS).

## Что реализовано в отдельной ветке

- Единая резервная копия JSON: **все сохранённые** документы СОП (включая версии, исходные/отрисованные фото и разметку) плюс отдельные исследования ФРВ, в том числе архивные.
- SHA-256 всего файла и отдельного переносимого СОП, проверка всех записей до импорта. Повреждённые архивы отвергаются до записи.
- Импорт с предварительным планом и подтверждением: отсутствующие записи добавляются, совпадающие пропускаются, конфликтующие ID восстанавливаются под новым ID, без перезаписи; повторный импорт не должен создавать новые дубликаты.
- При совпадении опубликованного номера импортируемая публикация становится **черновиком**, чтобы не нарушать уникальность. Сохраняется архивная принадлежность ФРВ.
- Выделенная запись для каждого документа/исследования, откат новых записей и новых фото при отказе. Поскольку базы СОП/ФРВ/фото разные, это компенсирующий откат, не одна общая транзакция.
- Сохранение одного исследования ФРВ из разных вкладок защищено проверкой ревизии в пределах одной транзакции IndexedDB. Вторая вкладка получает предложение «Сохранить правки отдельной копией»; оригинал не переписывается.
- Кнопки резервной копии добавлены в существующую «Библиотеку СОП», отдельный узкий контроль конфликта — в строку сохранения Анализа ФРВ. Нет новых вкладок и большого параллельного UI.

## Границы и риски

- Экспортируются **сохранённые** документы, а не несохранённый редакторский черновик. Перед экспортом следует сохранить текущий СОП в библиотеку. Для исследований ФРВ выполняется flush автосохранения.
- После переноса на другой путь файла file:// браузер может завести другое локальное хранилище. Восстановление из скачанной копии возможно, но реальные разные пути и политики сетевого диска требуют проверки на ПК.
- Два окна защищены от потери изменений **при сохранении одного исследования ФРВ**. Совместная многопользовательская работа над СОП и сетевая синхронизация — отдельная тема, не заявлять как решённую.
- При конфликтной публикации импорт делается черновиком. Переназначение ссылок на исследование FRV в копии СОП учитывается через ID map.
- Не менять AI-прокси Yandex, модельную маршрутизацию, локальные ExcelJS/ISO, экспорт XLSX с фотографиями, TWI из СОП, существующие разделы ФРВ. Видео, секундомер и внешний импорт замеров Excel не добавляются.
