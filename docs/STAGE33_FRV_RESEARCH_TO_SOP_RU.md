# Stage33 — самостоятельный «Анализ ФРВ» → новый проект СОП

**Статус: кандидат в отдельной ветке; пользовательская приёмка и окончательная CI ещё требуются.** Принятая Stage32.2 не менялась в `main`. [Отправной аудит](https://github.com/shonentez-afk/SOP-generanjr/blob/main/docs/FRV_ANALYSIS_UX_AUDIT_STAGE32_RU.md).

## Назначение двух вкладок

- **«⏱ ФРВ»** остаётся привязанной к уже заполненным шагам СОП и экспортируется привычным листом ФРВ в XLSX. Теперь ВДЦ (галочка) означает **оставшуюся часть** времени шага после явно указанных М1/М2, так что категории не удваивают длительность. Отрицательные числа и сумма М1+М2 больше времени шага блокируют экспорт. Уточнены единицы времени в Excel: секунды для сводных чисел, `ч:м:с` для колонки длительности. Макет, фотографии и инструменты экспорта Stage32.2 не менялись.
- **«📊 Анализ ФРВ»** — независимое начало работы. Описание изучаемой операции вводится прямо в разделе. Данные исследования хранятся в `state.frvStudy`; редактор СОП может оставаться пустым. Пользователь измеряет время, классифицирует затраты, ищет потери и **по собственному решению создаёт новый проект СОП**. Это необязательная связь, а не требование проходить ФРВ перед СОП/TWI.

## Улучшение UX

- Сохранена отдельная вкладка «Анализ ФРВ», без прежней 19-колоночной видимой таблицы. В основном режиме доступны действие, фактические секунды, категория ВДЦ/М1/М2/ожидание/перерыв, комментарий, расстояние и пометка **«В СОП»**. Нормализованное действие, качество, безопасность, инструмент, материалы, детали потерь, доказательства доступны через «Подробнее» для каждой строки.
- Два независимых источника: **наблюдённые факты и секунды** vs **неизмеренные предложения ИИ**. «Предложить действия» на основании описания показывает черновики отдельно; они становятся наблюдениями только по подтверждению пользователя, но всегда с временем `null`. ИИ не создаёт новый измеренный цикл.
- Без ИИ сразу доступны итоговое время, ВДЦ, М1, М2, ожидание, незаполненные замеры, самые длительные действия, сравнение полных реальных циклов, среднее и разброс (CV). «Предложить улучшения с ИИ» — необязательная рекомендация, вывод сохраняет RAW и времена. Если данные изменились после ИИ — анализ отмечается устаревшим.
- При повторных замерах одноимённые действия с совпадающим порядковым номером собираются в проект шагов СОП; проектное время по умолчанию — **медиана реальных замеров**, сохраняется первичная длительность и идентификаторы источников. Пользователь может менять только отдельное *проектное* время. ИИ не определяет нормативное время.
- В проект СОП включаются только вручную отмеченные действия с измеренной длительностью. Потери, ожидание и перерывы при выборе категории снимают автоматическую пометку «В СОП». Пользователь при необходимости может сознательно вернуть её.

## Безопасная передача

1. «Подготовить шаги СОП» работает без ИИ и формирует проверяемый проект последовательности.
2. «Создать новый проект СОП» показывает предпросмотр и требует отдельного подтверждения. Без согласия `state.steps` не меняется.
3. Текущий СОП перед переключением **обязательно** сохраняется в localStorage (поля, шаги, ссылки на фото, история/черновик); сами фотографии остаются в IndexedDB. Если хранилище не позволяет записать копию, новый проект **не создаётся**.
4. После подтверждения создаются новые шаги и чистый черновик СОП. Сохраняются ссылки `frvSource` на реальные наблюдения/циклы и замеренные секунды; при переходе в формат редактора продолжительность округляется до целых секунд, исходное значение не изменяется и остаётся в `frvSource.observedTimeSec`.
5. «Вернуть предыдущий СОП» позволяет восстановить старый черновик через `applyDraft`, включая фотографические ссылки/восстановление из IndexedDB. Нельзя автоматически создать TWI при таком переходе.

## Приёмка перед main

На компьютере пользователя открыть HTML кандидата через `file://`, открыть **«Анализ ФРВ» в пустом приложении**, ввести 3–5 замеров, посмотреть итоги без ИИ, выбрать будущие шаги, создать новый проект СОП. Проверить, что уже открытый СОП нельзя случайно перезаписать и он возвращается по кнопке. Отдельно проверить XLSX с фотографиями Stage32.2, лист ФРВ, TWI из готового СОП и настройки Yandex-прокси.

**Не смешивать** направления ФРВ→СОП и СОП→ФРВ; нет обязательной цепочки ФРВ→СОП→TWI. Не объединять PR до зелёной CI и пользовательского «работает».

**Сохранение прослеживаемости:** `src/modules/documents/stage33-draft.js` сохраняет `frvSource` каждого шага в черновике (ID наблюдений, циклы, реальные и проектные секунды). При восстановлении, а также после закрытия/повторного открытия СОП эта связь не теряется. Старые документы продолжают загружаться.
