# Stage 22 A3.1 — защита рабочего СОП от запоздавших ответов ИИ

Дата: 19.11.2026. Версия: `releases/stage22-a3-ai-guard.html` (автономный Chrome/Edge `file://`, один HTML). Предыдущий принятый релиз: Stage21.

## Почему понадобилось изменение

Ранее генерация СОП/TWI, подсказки редактора/фото, анализ ФРВ и обсуждение ИИ-наставника после асинхронного `await aiAsk(...)` продолжали менять глобальный `state` без проверки, что пользователь всё ещё редактирует тот же документ и те же исходные данные. Это угрожало сохранности правок, фотографий, фактических измерений и дискуссий наставника.

## Изменения

1. `src/modules/ai/stage22-context-guard.js` — изолированный read-only API `aiGuardCapture(options)`, `aiGuardMatches(token)`, `aiGuardCanApply(token)`. Подписывает ID/версию/статус СОП, шаги, редакторские поля, изображения (по ссылкам, без дублирования их base64), а по запросу ФРВ, TWI или историю проверки. Не имеет доступа к сетевому транспорту и не записывает данные.
2. Контракт используется непосредственно перед применением ответа в `stage22-generate-sop.js`, `stage22-field-editor.js`, `stage22-review-task.js`, `stage22-dispute.js`, `stage22-study-ai.js`, `stage22-from-sop.js`.
3. Проверка учитывает изменения в ходе запроса; при несовпадении пользователь получает понятное сообщение, ответ не применяется. В споре с наставником устаревший ответ не записывается в историю уже открытого другого СОП; завершение запроса не перерисовывает чужие замечания.
4. По результатам полной проверки наставника обновлённые текущие замечания записываются в локальный черновик через существующий Stage21 контракт. Никаких изменений схемы хранения нет.
5. Stage22 собирается по `src/app/stage22-parts.json` и `tools/build_stage22.py` из 43 исходных JS-модулей в один HTML. Сетевых зависимостей или внешних JS-модулей не добавлено.

## Принцип «не ломать работающее»

Оставлены **без единого изменения** файлы `src/modules/ai/stage19-transport.js`, `src/modules/ai/stage19-protocol.js`, `src/modules/ai/stage19-prompts.js`. Адрес Yandex Cloud Cloud Function, все разрешённые модели, fallback, промпты и HTTP-контракт сохраняются. Также не затронуты ExcelJS 4.4.0, 60 локальных знаков ISO, фото/разметка и структура IndexedDB/localStorage/JSON/XLSX. TWI по-прежнему автоматически создаётся из СОП без обязательного ФРВ.

## Регрессионная проверка

- `python tools/build_stage19.py --verify-baseline`, `python tools/build_stage20.py --verify-release`, `python tools/build_stage21.py --verify-release`.
- `python tools/build_stage22.py --verify-release` и `--verify-static`.
- `python -m unittest discover -s tests -v`: полный набор прежних тестов + Node-проверка read-only подписи.
- `node --check` собранного JS.
- `python qa/stage22_browser_smoke.py`: все предыдущие Chrome `file://` тесты (фото/Excel/ISO/IndexedDB/наставник/история) и 10 сценариев AI с локальными моками (обычная генерация и запоздавшие ответы для СОП, TWI, полей, фото, ФРВ и наставника). Ни один тест не требует вызовов настоящего AI.
- Workflow: `.github/workflows/stage22.yml`. Фактическую приёмку и SHA фиксировать по GitHub Actions после PR.

## Ограничения

Stage22 — **A3.1, не завершённый A3**. Пока не изменяли транспорт, общий парсер HTTP/JSON, правила fallback/таймаутов. Не внедрён предпросмотр AI-замены уже существующего СОП/ФРВ; при повторном формировании TWI старые ручные поправки, существовавшие до запуска запроса, ещё требуют защиты в пакете A4. История повторных полных проверок пока не архивируется. Реальная Windows + Excel + корпоративная сетевая папка + живой Yandex Cloud требуют отдельной ручной приёмки.
