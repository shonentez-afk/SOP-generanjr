# Stage 23 — A3.2: исправление `null` и безопасная кнопка «Применить»

**Основание:** скриншот с карточкой «Улучшить → Шаг 1» при времени `00:55`. Наставник вернул рекомендацию увеличить длительность, но вместо конкретного значения выдал строку `"null"`. Приложение трактовало любую непустую строку как готовое исправление, показывало зелёный блок и кнопку «Применить». `parseDuration("null")` возвращает ноль, поэтому нажатие могло затереть корректное исходное время.

## Решение

1. `src/modules/review/stage23-safe-fixes.js` — независимый контракт `reviewNormalizeFixValue` и `reviewGetApplicableFix`. Строковые маркеры отсутствия значения не считаются исправлениями. Для времени требуется конкретная длительность в допустимом формате и положительное значение, отличное от текущего. Разрешены только поддерживаемые поля.
2. `src/modules/ai/stage23-protocol.js` — корректная нормализация `fixValue` в ответе проверки и `new_fix` в ответе наставника, при этом тексты промптов и транспорт AI не меняются.
3. `src/modules/review/stage23-render.js` — зелёный блок и кнопка появляются только если фактически существует применимое исправление. Нельзя отметить замечание исправленным, не изменив поле. Остальные действия (оспорить, отложить, открыть шаг) доступны.
4. `src/modules/documents/stage23-review-state.js` — текущее состояние проверки сохраняет правильное значение `fixValue=null`.
5. `src/modules/ai/stage23-dispute.js` — ответ наставника без `new_fix` не записывает текстовый маркер.
6. `src/app/stage23-parts.json` + `tools/build_stage23.py` — 44 модуля исходного кода собираются в автономный HTML.

## Приёмка

`python tools/build_stage23.py --verify-release --verify-static`, `python -m unittest discover -s tests -v`, синтаксис `node --check`, `python qa/stage23_browser_smoke.py`. Браузерные проверки выполняют ситуацию со скриншота без внешнего ИИ: `null` не виден, нет «Применить», время 55 секунд и статус замечания сохраняются. Затем проверяются конкретная длительность `02:10` (можно применить), невозможное время `00:65`, неподдерживаемое поле и документ с запретом редактирования. Полная функциональная регрессия Excel/фото/ISO/TWI/ФРВ/наставника остаётся обязательной.

**Не менялось:** URL и параметры Yandex Cloud-прокси, разрешённые модели, промпты, HTTP-транспорт, автономная ExcelJS, локальные ISO, редактор изображений, структура документов, TWI из СОП и необязательность ФРВ.

**Сфера:** программа находится в разработке, миграции старых архивов и совместимость пользовательских релизов не требуются. Существующие этапы в GitHub — только контрольные точки для проверки регрессий. A3 не закончен: далее унификация AI task schema и ошибок, потом A4 сохранение ручных корректировок TWI при повторной генерации. Для реального Yandex Cloud требуется отдельная проверка в рабочей сети.
