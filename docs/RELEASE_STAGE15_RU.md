# Stage 15 — встроенные знаки безопасности ISO 7010

Дата: 2026-11-18. Основание: пользователь сообщил, что пиктограммы долго загружаются и часть не появляется в корпоративной сети.

## Релиз и назначение

- Готовый **один HTML-файл**: `releases/stage15-local-iso7010-icons.html`.
- Восстановить сборку: `python tools/build_stage15.py`.
- Проверить битовую воспроизводимость: `python tools/build_stage15.py --verify-release`.
- Пакет исходных рисунков: `src/assets/safety/iso7010-part01.json` … `iso7010-part07.json` (60 оригинальных SVG, разложенных на семь частей для удобства сопровождения).
- Загрузка в интерфейсе: `src/modules/safety/local-iso7010-loader-stage15.js`.
- Растрирование для XLSX: `src/modules/safety/local-iso7010-export-stage15.js`.

## Что изменилось

Ранее 60 знаков ISO 7010 скачивались по цепочке Wikimedia Commons → wsrv.nl/images.weserv.nl с задержками, тайм-аутами, очередью из четырёх запросов и необязательным кэшем IndexedDB. Даже после попыток повторной загрузки некоторые картинки оставались пустыми.

Теперь все 60 векторных SVG **встроены непосредственно в HTML как JSON**, причём каталог сохраняет прежние коды (M, W, P), категории, названия и состояние выбора. Браузер сразу использует изображения через `data:image/svg+xml` без файлов рядом с HTML, HTTP, сервера, кэша и сети.

При формировании ExcelJS выбранные знаки локально отрисовываются на Canvas в PNG. Важное отличие от предыдущего кода — **XLSX не зависит от прокси изображений**. Если ранее выбранные пиктограммы хранились по ID, ID продолжают работать, миграция документов не нужна.

Ни одно из значений ИИ, Yandex Cloud-прокси, моделей, промптов или маршрутизации не изменено. Локальная ExcelJS, функциональность ФРВ, TWI, чек-листа, фото, библиотеки и документов не изменена. Телефон не рассматривается.

## Комплект и происхождение

- 20 предписывающих: `M...`.
- 23 предупреждающих: `W...`.
- 17 запрещающих: `P...`.
- Все 60 представлены в том же каталоге `ICON_LIB` без замены значений ID.
- Для W035 используется исходный файл `ISO_7010_W035_PD.svg`, для W079 — `ISO_7010_W079_color.svg`: обычных файлов с точными именами в используемой версии набора не было.
- Исходный комплект: [karlnorling/iso-safety-signs](https://github.com/karlnorling/iso-safety-signs), конкретная фиксация `628821bed43ec3dbb678a4ac6364eaf1e6982130`.
- Лицензия на пакет: MIT, файл `src/assets/safety/LICENSE_UPSTREAM_MIT.txt`. Её текст включён в готовый HTML.
- Отдельные оригинальные графические изображения происходят из Wikimedia Commons. **У каждого файла могут быть собственные автор и условия лицензии**; список исходных имён и blob SHA находится внутри JSON-частей. Файлы можно найти по шаблону `https://commons.wikimedia.org/wiki/File:ISO_7010_ИД.svg`; для W035/W079 пользоваться точными именами выше.
- Наличие пиктограммы в каталоге не означает автоматического подтверждения актуальности стандарта/сертификации. Для производственного применения ответственный специалист должен подтвердить корректность знаков и их названий согласно утверждённым документам предприятия.

## Проверка

CI: `.github/workflows/stage15.yml`.

1. Сборка по исходным файлам должна совпадать с зафиксированным релизом.
2. 60/60 кодов из оригинального каталога должны иметь SVG, без пропусков.
3. Контракты модулей и регрессионные тесты Stage 11–14 остаются зелёными.
4. Node проверяет синтаксис JS конечного HTML.
5. Реальный Chrome запускается через `file://` с заблокированными HTTP и HTTPS; проверяются 60 изображений в интерфейсе, 60 преобразований SVG→PNG для Excel, отсутствие сетевых запросов.

Проверка Chrome в CI использует настоящий браузер, но **не заменяет ручную проверку конкретного Windows Chrome/Edge**, реальной сетевой папки и устойчивого хранения фото/библиотеки. Настройки ИИ сохранены; для отправки запросов к ИИ интернет по-прежнему нужен.

## Обратимость

Stage 14 не изменён. При необходимости можно открыть `releases/stage14-desktop-ux-data-integrity.html`. Stage 15 меняет только источник графики знаков и их подготовку к XLSX, не изменяя форматы данных.
