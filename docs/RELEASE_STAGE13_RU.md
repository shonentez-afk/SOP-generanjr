# Stage 13 — неразрушающий фоторедактор

Дата: 2026-11-18.
Ветка: `feature/stage13-layered-photo-editor-20261118`.
Базис: `releases/stage12-local-exceljs-photo-studio.html`.

## Что изменено
1. Сохраняются три сущности: исходный `blob`, JSON-массив `annotations` и готовый `renderedBlob` для предпросмотра/Excel.
2. При повторном открытии редактора исходное фото и фигуры восстанавливаются отдельно; фигуры можно выделять, удалять, менять текст и перетаскивать.
3. В существующей IndexedDB `sop-builder-db-v3/stepPhotos` добавляются **необязательные поля записи**, версия БД и схема хранилища не меняются.
4. Для каждого сохранённого документа и его версии изображение дополнительно копируется под строковым ключом `sop-doc-photo:<documentId>:<stepId>`; активный редактор по-прежнему использует числовой `stepId`.
5. В JSON черновика/снимка библиотеки сохраняются только метаданные фото и разметка — без бинарных JPEG в localStorage.
6. Экспорт XLSX продолжает использовать готовое объединённое JPEG без изменения макета и формата.

## Что не изменено
Адрес ИИ-прокси Yandex Cloud, маршрутизация запросов, модели, промпты, правила ФРВ/TWI, интерфейс вне фоторедактора, ExcelJS 4.4.0 и остальные функции. Переход на иной прокси запрещён без отдельного указания пользователя.

- `src/modules/photos/stage13-photo-section.js` — фото/IndexedDB/редактор.

- `tools/build_stage13.py` — сборка одного HTML.

- Проверка: `python tools/build_stage13.py --verify-release`, `python -m unittest discover -s tests -v`.

## Подтверждённые проверки
- Синтаксис всех встроенных JS-скриптов: `node --check`, PASS.
- Chromium headless с имитацией localStorage/IndexedDB: загрузка тестового PNG, рамка, подпись, сохранение в отдельные base/rendered/annotations, повторное открытие и выбор ранее сохранённой подписи, PASS.
- В тесте проверено создание изолированной копии фото по ID документа и восстановление после замены активного рабочего фото, PASS.
- Бинарный пакет локальной ExcelJS и ИИ-секция по сравнению с Stage 12 не тронуты.

## Известные ограничения
- Полный прогон с реальной IndexedDB через `file://` на ПК пользователя не выполнялся: запуск браузера по внешнему или локальному URL в среде автоматизации заблокирован. Chromium-тест использовал **имитацию** IndexedDB. Требуется ручная проверка пользовательского браузера.
- Старые фото с уже запечёнными пометками нельзя разобрать на исходные фигуры; сохраняется возможность размечать их заново поверх.
- Отдельный скачанный JSON СОП и JSON в сетевой папке **пока не переносят бинарное фото на другой ПК**. Изоляция версий действует в IndexedDB одного браузерного профиля. Для межкомпьютерного переноса потребуется отдельный переносимый пакет (не входит в Stage 13).
