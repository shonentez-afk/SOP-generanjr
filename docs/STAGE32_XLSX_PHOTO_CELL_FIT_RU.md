# Stage 32 — фотографии в XLSX заполняют объединённые ячейки СОП

**Состояние: кандидат в ветке `feature/stage32-excel-photo-cell-fit-20261119`; до зелёной CI и пользовательской проверки не принят.**

## Установленная причина
В принятой Stage31 в `src/modules/excel/stage20-export.js` каждое фото шага вставлялось с фиксированным размером **150×95 px**, тогда как строка «Визуализация» имеет высоту **120 pt (~160 px)** и объединённые диапазоны `C:E`, `F:I`, `J:L` шириной примерно **330–340 px**. Поэтому картинки занимали менее половины ширины предназначенной им области.

## Исправление Stage32
- Используется **новый изолированный экспортный модуль** `src/modules/excel/stage32-export.js` вместо `stage20-export.js`; другие 57 модулей не меняются.
- Фото вставляется на всю площадь соответствующей объединённой ячейки с отступами **4 px**: `C:E`, `F:I`, `J:L` на строках визуализации. Вместо константы 150×95 координаты вычисляются по текущим размерам строк и колонок.
- ExcelJS 4.4.0 получает двухъячеечные анкеры с прямыми **EMU-координатами** (для ширины в символах и высоты в пунктах), без зависящих от ширины колонок дробных смещений. Атрибут `editAs=oneCell` не задаётся: фото масштабируется вместе с ячейками.
- **Компромисс:** содержимое снимка не обрезается. Чтобы полностью заполнить ячейку, Excel может изменить визуальные пропорции узких/портретных изображений; исходные фото и их аннотации неизменны.
- Не изменены шапка/заголовки, строки/столбцы, формулы, логотип, локальные ISO-пиктограммы, ФРВ, чек-лист, TWI, генерация СОП, импорт XLSX, база/хранилище фото и настройки Yandex Cloud.

## Автоматическая проверка
- `tools/build_stage32.py` + `src/app/stage32-parts.json` → автономный `releases/stage32-excel-photo-fill-browser-candidate.html` с 58 JS-модулями.
- `tests/test_stage32.py`: точность EMU-анкерных прямоугольников по всем трём объединениям и следующей строке; остальные модули/статическая оболочка сохранены.
- `qa/stage32_excel_photo_cell_fit.py`: полный Chrome Stage31 regression, затем настоящий XLSX с 4 фото разных пропорций. Проверяются SHA оригинальных изображений в ZIP, координаты `xl/drawings/*.xml`, заполнение 94–100% ширины и высоты объединённых ячеек, Excel-импорт обратно с 4 фотографиями, листы СОП/ФРВ/Чек-лист.
- `.github/workflows/stage32.yml`: Linux и Windows Chrome; HTML и образец XLSX доступны как GitHub Actions artifact.
- Полную визуальную приёмку **в Microsoft Excel на пользовательском ПК** нельзя заменить только OOXML-проверкой: пользователь должен открыть Excel-файл, оценить заполнение всех трёх фотообластей и печатный вид.

**Текущая рабочая версия пока Stage31 на main.** Сетевую папку двух ПК CI не проверяет. Не включать `SOP_ENABLE_MODEL_ROUTING`, не трогать Yandex-прокси, отдельную ФРВ и TWI из СОП.
