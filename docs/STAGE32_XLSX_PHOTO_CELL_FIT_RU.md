# Stage32.2 — правильные пропорции фотографий и полный экспорт XLSX (20.11.2026)

**Новый кандидат Stage32.2 в PR #27, ещё не принят пользователем.** Рабочая версия в `main` — Stage31. Ранее пользователь прислал второй скриншот: фотографии в Stage32.1 теперь большие, но фото человека непропорционально растянуто по горизонтали, третий слот пуст. По одному скриншоту нельзя определить, был ли снимок вообще прикреплён к третьему шагу.

## Исправление
- Экспортный модуль `src/modules/excel/stage32-export.js` теперь формирует в каждой заполненной фотообласти **два слоя**: первый — лёгкий фоновый JPEG с мягко размытым исходным снимком, второй — **оригинальное изображение без перекодирования, обрезки и изменения пропорций**, вписанное по центру. Это заполняет весь прямоугольник без искажения лица, схемы или текста. Входная фотография остаётся исходной как отдельная картинка в XLSX, а при обратном импорте выбирается последняя (исходная).
- Вычисление ширины изображения использует фактическую Excel-геометрию с безопасным полем **6 px** по каждой стороне, без прежнего избытка `+5 px` на каждую колонку. Фон не перекрывает соседние диапазоны `C:E`, `F:I`, `J:L`, а передний слой остаётся внутри соответствующей группы.
- Неподдерживаемые ExcelJS элементы `oneCellAnchor editAs` и нулевое преобразование формы устраняются по-прежнему. Число ожидаемых иллюстраций при исправлении XML теперь `2 ×` число шагов с фото. При отсутствующем флаге/данных фотографии пустая фотообласть не заполняется выдуманным изображением; если фото обозначено, но не найдено, экспорт выдаёт ошибку.
- Новый файл однозначно отмечен суффиксом **`_ФОТО_STAGE32_2.xlsx`**. Статус: «Фото без искажений — Stage 32.2». Не путать с Stage32/32.1.
- Сохраняются: логотип, ISO, 3 листа, расчёты времени, TWI из СОП, отдельная ФРВ, файл данных/черновик, редактор фотографий Stage31, Yandex Cloud и `SOP_ENABLE_MODEL_ROUTING` (выключен). В `main` изменений нет.

## Stage32.1 — исправление по скриншоту пользователя

**Проблема не была устранена в Microsoft Excel.** Пользователь предоставил скриншот и подтвердил, что XLSX создан последней Stage32: три изображения продолжают отображаться небольшими в левых верхних углах широких объединённых ячеек. Предыдущие тесты Stage32 измеряли только охват диапазона координатами двухъячеечной привязки, но не реальную ширину изображения в Excel. Сообщать об устранении ошибки на основании старого CI запрещено.

**Изменено в Stage32.1:** у каждого фото теперь используется стандартный `oneCellAnchor` c **явным размером xdr:ext** в пикселях, вычисленным по объединённым колонкам и 120-pt строке. ZIP нормализуется после работы ExcelJS 4.4: у `oneCellAnchor` удаляется неподдерживаемый `editAs`, нулевой `a:xfrm` и запрет изменения пропорций; остальные компоненты ZIP копируются как есть. Фото остаются в исходных байтах (SHA сохраняется), логотип/ISO/листы/формулы не затрагиваются. Прототип проверен на настоящем XLSX, который открывается openpyxl с OneCellAnchor и корректными ext. Это изменение уменьшает зависимость отображения от того, как Excel интерпретирует `twoCellAnchor`.

**Защита от старого файла:** новый скачиваемый XLSX содержит в имени `_ФОТО_STAGE32_1.xlsx` и строку успеха «Фото в ячейках — Stage 32.1». Если их нет, открыт старый HTML или старый XLSX.

**Новая автоматическая проверка:** тестировать полноразмерные значения `xdr:ext`, отсутствие неподдерживаемых элементов в `oneCellAnchor`, исходные SHA всех фото и повторный XLSX-импорт. **Визуальная приёмка в реальном Microsoft Excel ещё не пройдена.** До ответа пользователя не объединять PR #27 в `main`.

## Установленная причина
В принятой Stage31 в `src/modules/excel/stage20-export.js` каждое фото шага вставлялось с фиксированным размером **150×95 px**, тогда как строка «Визуализация» имеет высоту **120 pt (~160 px)** и объединённые диапазоны `C:E`, `F:I`, `J:L` шириной примерно **330–340 px**. Поэтому картинки занимали менее половины ширины предназначенной им области.

## Исправление Stage32
- Используется **новый изолированный экспортный модуль** `src/modules/excel/stage32-export.js` вместо `stage20-export.js`; другие 57 модулей не меняются.
- Фото вставляется на всю площадь соответствующей объединённой ячейки с отступами **4 px**: `C:E`, `F:I`, `J:L` на строках визуализации. Вместо константы 150×95 координаты вычисляются по текущим размерам строк и колонок.
- ExcelJS 4.4.0 получает двухъячеечные анкеры с прямыми **EMU-координатами** (для ширины в символах и высоты в пунктах), без зависящих от ширины колонок дробных смещений. Атрибут `editAs=twoCell` задаёт масштабирование вместе с размером ячеек Excel (поддерживаемая конструкция OOXML).
- **Компромисс:** содержимое снимка не обрезается. Чтобы полностью заполнить ячейку, Excel может изменить визуальные пропорции узких/портретных изображений; исходные фото и их аннотации неизменны.
- Не изменены шапка/заголовки, строки/столбцы, формулы, логотип, локальные ISO-пиктограммы, ФРВ, чек-лист, TWI, генерация СОП, импорт XLSX, база/хранилище фото и настройки Yandex Cloud.
