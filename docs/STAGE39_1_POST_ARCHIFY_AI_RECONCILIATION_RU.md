## Решение о количестве причин — без изменения корпоративского XLSX

**Рекомендуемое поведение: одна общая, короткая причина на шаг по умолчанию, если она действительно объясняет все его критические КМ.** Для нескольких различных, независимо значимых рисков/смыслов — отдельные `1. ...\n2. ...` в **том же** `steps[].reason`, только по необходимости. Не создавать три причины только потому, что есть три KM. Не требовать соотношения 1:1. Сохранить ручную редактуру и экспорт неизменными.

Для примера «Осмотреть электроинструмент» возможен осторожный общий черновик: «Выявить видимые повреждения электроинструмента до его использования». Это **не утверждение**, что кабель/ввод/корпус имеют именно названные ИИ риски короткого замыкания, поражения током, герметичности и т. п. Эти конкретные причины подтверждаются техническим специалистом по инструкции оборудования.

Если поле уже содержит три нумерованные причины, ИИ **не должен молча заменять** их одной общей. Переход «3→1» допустим только после отдельного явного решения пользователя с сравнением старого и нового текста, проверкой сохранения содержания и указанием, что отдельные объяснения будут объединены. При недостатке данных оставить исходное поле.
