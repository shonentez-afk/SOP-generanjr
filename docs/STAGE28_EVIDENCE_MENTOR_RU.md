# Stage 28 — единый доказательный ИИ-наставник СОП

**Статус:** кандидат Stage28 в ветке `feature/stage28-evidence-mentor-20261119`, **не объединять до зелёного CI и пользовательской проверки**.

**Контрольная база:** Stage27 принят пользователем и слит в `main` (PR #22, squash `f34465c7d0832d0b60346680ca7f4936f90512dd`). Stage26 и Stage27 исходники/релизы сохранены. Настройки и URL действующего Yandex Cloud-прокси не менялись, `SOP_ENABLE_MODEL_ROUTING` по-прежнему выключен.

**Итоговый файл:** `releases/stage28-evidence-mentor-browser-candidate.html`. Один автономный HTML для настольных Chrome/Edge `file://`; сборка `python tools/build_stage28.py` по `src/app/stage28-parts.json` — 55 JS-модулей.

## Что изменено

1. **Единый источник результатов наставника.** `Проверить весь СОП` по-прежнему объединяет детерминированные проверки и один запрос ИИ. Ранее кнопка `Логика шагов` делала второй похожий AI-запрос; в Stage28 она показывает смысловые замечания из уже выполненной общей проверки, а при изменении шагов вызывает только выборочную перепроверку. Никаких скрытых AI-повторов.
2. **Доказательность.** Промпт просит модель указать исходное поле и дословную цитату; исходный код проверяет наличие цитаты в реальном тексте указанного шага/поля. В общей карточке отображаются «Основание по СОП», «Гипотеза» либо «Требует уточнения». Без подтверждения опасные предположения нельзя автоматически применять как готовую правку.
3. **Проверка по TWI-логике.** Анализируется цепочка действие → необязательные 0–3 Key Points → причина важности → критерий результата; отсутствие Key Points/фото само по себе не является ошибкой. Модель не должна придумывать нормативы, допуски или средства защиты.
4. **Содержательные фотоподсказки.** Проверка знает о наличии прикреплённого фото, `visualMarkers` и `photoHint`. Внутри старой сводки раскрывается необязательная строка о кадрах, рекомендованных **только по тексту**. Пиксели/изображения не отправляются модели, качество кадра не оценивается и обязательные фотографии не навязываются.
5. **Проверка изменённых шагов.** После успешной полной проверки сохраняются подписи шагов, их порядка и метаданных. Если изменены отдельные шаги, кнопка «Проверить изменённые шаги» отправляет только их и непосредственных соседей. Прочие замечания, статусы «Применено/Оспорено/Отложено» и история переписки сохраняются. При изменении состава, порядка, исходного описания или общих условий безопасности переключение идёт на полную проверку. Если текст не менялся, второй запрос не отправляется.
6. **Не теряем данные при сетевом сбое.** Ошибка облачного наставника не уничтожает прежние замечания и диалоги; первоначальная проверка без сети показывает только автопроверки с явной оговоркой.
7. **Сохранение.** Проверка хранит `reviewMeta` в существующем `reviewState` внутри локального черновика и снимка библиотеки. Дополнительно сохраняются источник и тип доказательства каждого замечания. Не вводится новый IndexedDB, формат фото или второй документ.

## Интерфейс

**Новых панелей нет.** Сохраняется проверенный пользователем дизайн: в строке 4 постоянно видимых кнопок «Уточнить СОП», «Логика шагов», «По аналогии», «Сравнить версии» и старая кнопка «Проверить весь СОП». Улучшения доказательности и фотоподсказки появляются в **том же старом блоке результата**. Выборочная кнопка появляется в сводке уже проверенного СОП, а не в отдельном меню.

## Что оставлено нетронутым

- Адрес и модели Yandex Cloud, транспорт, ExcelJS/OOXML, локальные 60 ISO 7010;
- Редактор фото и разметка, импорт/экспорт XLSX, библиотека/сетевая папка;
- ФРВ по желанию пользователя; TWI автоматически только из СОП с защитой ручных правок;
- Никаких изменений исходных наблюдений, длительности шагов и изображений ИИ-проверкой;
- Мобильный интерфейс не разрабатывается.

## Ограничения

- Реальная проверка корпоративного Yandex Cloud и сетевой папки выполняется пользователем: CI работает с замещёнными ответами ИИ и без сети.
- Совпадение цитаты доказывает только наличие фрагмента текста, но не истинность технологического вывода: решения по безопасности принимает инженер.
- Проверка соседних шагов учитывает текстовый контекст, но не заменяет полный аудит после существенного изменения документа.
- Если JSON входа превышает безопасный лимит, онлайн-анализ не выдаётся за полный: программа сообщает об ограничении. Вопросы о применимости нормативов проверяются отдельно.

## Ручная приёмка

Открыть Stage28 HTML в Chrome/Edge на ПК, загрузить реальный тестовый СОП с несколькими шагами. Выполнить полную проверку, затем «Логика шагов»: не должно быть второй параллельной истории или дубликатов. Исправить один шаг и нажать «Проверить изменённые шаги»; остальные замечания и ответы должны остаться. Проверить подтверждения источников, работу «Применить/Оспорить/Отложить», текстовые рекомендации фото, сохранение черновика и повторное открытие. Повторить генерацию СОП/TWI, ФРВ, экспорт XLSX с фото. Только после этого обсуждать merge в main.

**Следующий пакет после приёмки Stage28:** пакет C (по утверждённому плану) — согласование необязательной ФРВ → СОП → автоматически сгенерированного TWI, без создания отдельного TWI-конструктора.
