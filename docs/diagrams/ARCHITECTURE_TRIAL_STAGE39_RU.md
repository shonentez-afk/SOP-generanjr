**Снимок:** `main@4cf1a467e912984cb98d6dc969ab10eb685f458b` (23.11.2026).  
**Цель:** объединить блок-схемы и карту реальных зависимостей в одном автономном HTML, не менять программу.

## Выполнено

1. Создан [единый HTML-просмотрщик](sop-stage39-unified.html): общая архитектура, подробные запросы ИИ, интерактивная карта 67 активных JS-модулей, описание восьми представлений LikeC4. Вся визуальная информация и граф встроены в файл, дополнительных скриптов с сервера не нужно.
2. Подготовлена модель [LikeC4](likec4/model.c4) и [8 представлений](likec4/views.c4), описывающих систему, подсистемы, СОП, ИИ, TWI, ФРВ, хранение и Excel. **Официальный LikeC4 CLI не запускался и вывод его сборки не заявляется проверенным.**
3. Выполнено собственное чтение исходников через доступ к GitHub: все **67** файлов, перечисленных в `src/app/stage39-parts.json`, без исторических исходников. Результат: [полный JSON графа](stage39-verified-callgraph.json) и [7 партий лексического сканирования](data/).
4. В исходном коде не менялись функции, бандлы, тесты, прокси и корпоративные XLSX.

## Как проверить на ПК / в GitHub Actions

### LikeC4 — проверка модели и сборка сайта

В локальной копии репозитория с Node.js 20+:

```bash
cd docs/diagrams/likec4
npx likec4 start
```

Для полноценного сайта:

```bash
npx likec4 build -o dist
```

Проверить все 8 views. До запуска `build` — только подготовленный исходник, а не официально собранный сайт. Никаких установок/сборки Stage39 для просмотра готового `sop-stage39-unified.html` не требуется.

### CodeFlow — сравнительная проверка

Запустить браузерный [CodeFlow](https://codeflow-five.vercel.app/) и указать `shonentez-afk/SOP-generanjr`, либо выбрать локальные исходники. **Обязательно отделить 67 файлов из Stage39 manifest от множества исторических src/modules** и не делать вывод о циклических импортах: Stage39 объединяет глобальные скрипты, а не ES-модули. Сравнить ключевые рёбра с [нашим графом](stage39-verified-callgraph.json).

### GitNexus — только после лицензирования

Уточнить правомерность использования PolyForm Noncommercial для целевого корпоративного сценария. Если применение разрешено, проверить Node 22.18+ или 24.11+, выполнять только локальную индексацию `gitnexus analyze --index-only`, без подключения внешнего чата и без изменений проекта. Параметр `--index-only` описан в официальной документации. Результат сравнить с прямыми связями `aiAsk`, `generateSOP`, `reviewEntireSOP`, `generateTwiPlan`, `frvStudyAnalyze`. В нашем сканере ссылки на некоторые функции-обработчики без скобок не распознаются — это ожидаемый пробел.

## Регрессионные ограничения

- Никаких изменений `main`, `releases/`, `src/`, `proxy/` или `qa/`.
- Не запускать непрозрачные скрипты установки третьих лиц в корпоративском окружении без проверки.
- Не объявлять CI/browser/официальный LikeC4 PASS до получения логов.
- Никаких обязательных серверов или сетевых JS для пользовательского автономного HTML.
- Архитектурная карта и граф зависимостей — разная степень достоверности; визуальные стрелки первого уровня не являются автоматически обнаруженными AST-связями.
