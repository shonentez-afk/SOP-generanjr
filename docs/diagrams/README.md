## Детальная схема запросов ИИ (Stage39)

- [Интерактивная карта 15+1 AI task](sop-stage39-ai-interactive.html) — 15 групп доступных пользователю задач (с динамическим семейством `edit_*`) и отдельная реализация `stage27_mentor`, **не вызываемая штатным UI**. Для каждой указаны входные данные, параметры запроса, ожидаемый ответ, проверки, условия изменения исходных данных и ссылка на код.
- [Archify Dataflow JSON](sop-stage39-ai.dataflow.json) — поток браузер → формирование задачи → `aiAsk()` → Yandex Cloud Function → YandexGPT → проверка ответа → применение.
- Обычная кнопка «Логика» в Stage39 вызывает `stage28ReviewLogic()` и использует единый запрос `review`; **второй сетевой запрос `stage27_mentor` не должен считаться штатным**.
- Все JSON-примеры схематические; не являются реальными ответами от Yandex или доказательством реальных технических параметров.
- На стороне прокси при `SOP_ENABLE_MODEL_ROUTING=OFF` выбирается базовая модель вне зависимости от выбранного `model` в браузере; визуальный селектор не подтверждает фактическое переключение модели.
- HTML создан отдельно, не официальным CLI Archify. `finalize` официального CLI для AI Dataflow пока не запускался.


## Рендер официальным Archify

В каталоге установленного `tt-a1i/archify` с доступным Node.js 18+:

```bash
node bin/archify.mjs finalize architecture \
  /path/to/SOP-generanjr/docs/diagrams/sop-stage39.architecture.json \
  /path/to/SOP-generanjr/docs/diagrams/sop-stage39-archify.html \
  --repo-root /path/to/SOP-generanjr --quality showcase --json
```

Должна быть доступна чистая рабочая копия проекта на зафиксированной ревизии. Выходной путь `meta.output` — `docs/diagrams/sop-stage39-archify.html`. До успешной проверки `finalize` нельзя утверждать, что официальная схема прошла валидацию Archify.

## Архитектурные ограничения

- 67 исходных JS-модулей собраны в **один автономный HTML для ПК**; не обозначать их микросервисами.
- AI-запрос: браузер → Yandex Cloud Function → YandexGPT. `SOP_ENABLE_MODEL_ROUTING` выключен.
- TWI генерируется **из СОП**, а не непосредственно из ФРВ; ручные исправления TWI защищены.
- Отдельное исследование ФРВ может перенести предложения в новый СОП только после просмотра, подтверждения и резервного копирования.
- Корпоративский XLSX СОП: три листа, сохранение фотографии и нумерованных причин в одной ячейке. Печатный TWI XLSX: два листа.
- IndexedDB содержит локальные документы/медиа; внешняя сетевая папка опциональна. Совместная эксплуатация на двух ПК не подтверждена.
