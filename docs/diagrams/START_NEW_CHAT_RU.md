## 1. Цель

Построить **единую многоуровневую интерактивную карту программы**, где можно изучать общую архитектуру СОП/TWI/ФРВ, фактические ИИ-запросы и ответы, зависимости функций между 67 JS-модулями, оценивать возможные последствия изменения кода. Пользователь просил оставить все в одном HTML и вести схему отдельно от разработки рабочей программы.

Изменения в этом PR исключительно документационные — каталог `docs/diagrams/`. `src/`, `releases/`, `proxy/`, `.github/`, XLSX, тесты и `main` не изменены.

## 2. Главный результат

**[Единая интерактивная HTML-карта](sop-stage39-unified.html)** — файл `docs/diagrams/sop-stage39-unified.html`.

Четыре вкладки:
1. **Общая архитектура** — 17 логических компонентов и 23 связи, описание модулей и переходы к исходникам.
2. **Запросы ИИ** — 16 описанных групп (15 штатных и одна сохранённая функция `stage27_mentor` без UI-вызова): входные данные, промпт, ожидаемый JSON/текст, валидация, применение и ограничения.
3. **Зависимости 67 модулей** — поиск, фильтр по подсистеме, список вызывающих/вызываемых файлов, имена функций, ссылки на конкретные строки GitHub и быстрые переходы к наиболее связанным модулям.
4. **LikeC4** — каталог 8 представлений, ссылки на оригинальную `.c4` модель и переходы на соответствующие разделы карты. **Это ещё не собранный официальный LikeC4-сайт.**

Вложенные исходные схемы сохранены и отдельно: `sop-stage39-interactive.html` и `sop-stage39-ai-interactive.html`. HTML автономный (все данные и JS встроены), его можно скачать и открыть локально в Chrome/Edge. Переходы к исходникам на GitHub требуют интернет.

## 4. Что подтверждено анализом Stage39

Из `src/app/stage39-parts.json` извлечены **ровно 67 активных модулей**. В репозитории есть более старые файлы Stage19/Stage22 и т. д.; нельзя автоматически считать каждый файл из `src/modules/` частью актуальной сборки.

На основе чтения всех 67 файлов и поиска прямых ссылок между именованными глобальными функциями получено:

| Показатель | Результат |
|---|---:|
| Файлов в манифесте Stage39 | 67 |
| Объявлений функций верхнего уровня, распознанных сканером | 430 |
| Возможных межфайловых рёбер | 258 |
| Прямых статических ссылок на функции из других файлов | 995 |
| Файлов, участвующих хотя бы в одном таком ребре | 63 |

Важно: это **не результат запуска CodeFlow/GitNexus**, не AST-доказательство и не трасса исполнения. Динамические вызовы, callback-ссылки без `()`, HTML-обработчики, строки и шаблонные литералы могут отсутствовать в карте.

**Модули с наибольшим количеством прямых входящих ссылок:**

- `shared/stage19-ui-helpers.js` — 46 вызывающих файлов / 376 упоминаний вызовов.
- `documents/stage33-draft.js` — 27 / 81.
- `frv/stage35-study-model.js` — 7 / 59.
- `documents/stage27-db.js` — 8 / 51.
- `ai/stage26-transport.js` — 9 / 32.

Это **потенциальные центры связанности, не доказанные ошибки**. Четыре файла не вошли в найденный граф прямых вызовов — это не означает, что они не используются: они могут хранить объявления/константы либо подключаться иным способом.

**ИИ:** сканер нашёл 14 прямых обращений к `aiAsk()` в 7 файлах. Их количество не равно числу сетевых запросов при одном действии пользователя. Штатная кнопка логической проверки использует `stage28ReviewLogic` → общий `review`; отдельная функция `stage27ReviewLogic` с задачей `stage27_mentor` осталась в коде, но не вызывается через текущий UI.

## 5. Проверка схем — фактический статус

**Выполнено и проверено:**
- Последняя структура HTML и обе вложенные схемы прочитаны из GitHub.
- Встроенные JSON схем, списки AI task и полный граф разбираются без ошибок.
- Синтаксис трёх встроенных JS-сценариев (оболочка, общая карта, карта ИИ) проверен средствами JavaScript: PASS.
- Тестирование логики переходов в имитации DOM: PASS для повторного открытия того же раздела, LikeC4 → выбранный блок СОП, AI → выбранный блок ФРВ с ожиданием загрузки iframe.
- Исправлено лишнее перезагружание iframe и потеря выбора узла при переходах между вкладками.
- Вкладка зависимостей дополнена быстрым просмотром трёх наиболее связанных модулей.
- Проверка списка изменённых файлов PR #37: изменения ограничены `docs/diagrams/` на момент проверки.

**НЕ выполнено / нельзя объявлять PASS:**
- Полноценный браузерный прогон **оригинального HTML** в Chrome/Edge с визуальной приёмкой (из среды не получилось скачать GitHub-артефакт в контейнер).
- Запуск добавленного `node docs/diagrams/qa/verify-unified-map.mjs` на локальной копии репозитория; это первое действие для следующего чата/ПК.
- Официальный `likec4 build` и проверка валидности `.c4`.
- Официальный рендерер Archify `finalize`.
- Реальный анализатор CodeFlow и индексация GitNexus.

Особенность проекта: все активные исходные модули собираются **в один автономный HTML и общий JS runtime**; не приписывать им микросервисную архитектуру или реальные import/export-зависимости.

## 8. Границы ответственности и пожелания пользователя

- **Этот чат:** схемы архитектуры, многоуровневая карта, потоки ИИ, поиск связанности, QA схем, документация.
- **Основной чат разработки:** исправления ИИ и интерфейса СОП, рабочие релизы, экспорт XLSX, тестирование программы.
- Не менять работающие генерацию СОП/TWI, Yandex Cloud proxy, ФРВ, ExcelJS и Excel-шаблоны из этого направления.
- Причины могут иметь нумерацию `1.`, `2.` в **одном поле корпоративского шаблона**.
- TWI создаётся только из СОП, не напрямую из ФРВ.
- Фактические замеры ФРВ и RAW не должны изменяться ответами ИИ.
- Документация должна отличать **подтверждённую связь в коде, эвристическое предположение и непроверенный инструмент**.
- После каждого значимого изменения карты обновлять файл для передачи новому чату.
