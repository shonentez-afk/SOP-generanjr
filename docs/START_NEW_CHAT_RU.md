## Задача
Продолжать конструктор стандартных операционных процедур (СОП) Технониколь. Разработку вести модульно, для пользователя **сохранять один файл HTML с запуском двойным щелчком** в браузере ПК. НЕ подменять проект на ТОиР-конструктор: он был донором только встроенного фоторедактора.

## Обязателен аудит перед любыми изменениями
2026-11-18 проведён UX/UI-аудит Stage 13: `docs/UX_UI_AUDIT_STAGE13_RU.md`.
**ПЕРВЫМ делом исправить подтверждённый P0: фото из импортированного XLSX теряется после восстановления черновика.** Затем P1/P2 согласно отчёту. Не выдавать встроенный self-test 9/9 за полную регрессию.

## Актуальная версия Stage 13 — неразрушающий фоторедактор
`releases/stage13-layered-photo-editor.html` — единый HTML с исходным фото + редактируемой JSON-разметкой + готовым JPEG. Фото изолировано по документам и версиям в IndexedDB. Детали: `docs/RELEASE_STAGE13_RU.md`. Сборщик: `tools/build_stage13.py`. Stage 12 остаётся архивом предыдущей версии.

**Настройки ИИ и Yandex Cloud-прокси НЕ МЕНЯТЬ без прямого требования пользователя.** Ни локальная ExcelJS, ни фоторедактор не должны менять ИИ-модуль.

## Предыдущая готовая версия — Stage 12
`releases/stage12-local-exceljs-photo-studio.html` — текущий отдельный HTML с двумя перенесёнными функциями: локальная ExcelJS 4.4.0 и расширенный редактор фотографий. Подтверждено локальными проверками JS и Chromium с ограничениями среды. `tools/build_stage12.py` воспроизводит релиз из базовой Stage 11 и отдельных модулей. Описание: `docs/RELEASE_STAGE12_RU.md`.

**Нельзя изменять настройки ИИ, исходный прокси Yandex Cloud, модели, промпты и маршрутизацию запросов без отдельной команды пользователя.**

## Начальный эталон
`releases/stage11-photo-editor.html` — перенесённый из предыдущего чата исходник Stage 11 с редактором фотографий. Эта версия — baseline для регрессии, не заявлять полное функциональное тестирование без фактического запуска.

## Запреты
- Не переписывать бизнес-логику при структурном разделении; сначала сохранить поведение.
- Не ломать поля СОП, порядок шагов, фотографии, связку с ФРВ, TWI, экспорт/импорт XLSX, библиотеку и архив.
- Не менять структуру IndexedDB/localStorage, ключи, версии документов без миграции.
- Не менять способ запуска (один HTML, без веб-сервера).
- Не добавлять реальные персональные данные, фото, внутренние СОП, секреты и API-ключи в Git.
- Отделять неподтверждённое от проверенного; не выдавать план за реализацию.

## Порядок при продолжении
1. Прочесть README.md, этот файл, CURRENT_STATUS_RU.md, ARCHITECTURE_RU.md и CHANGELOG_RU.md.
2. Проверить состояние ветки/PR/CI и фактический код; не полагаться только на чат.
3. Сопоставить сборку с baseline: проверка равенства/осмысленного diff и регрессионные сценарии.
4. Выполнять изменения в отдельной ветке, затем PR; зафиксировать тесты и обновить CURRENT_STATUS_RU.md.
5. После каждого этапа приложить готовый HTML и отметить текущую версию, SHA и ограничения.
