## STAGE42 — ИСПРАВЛЕНИЕ НУМЕРОВАННЫХ КМ ПО СКРИНШОТУ — 25.11.2026

- **Новая проблема:** на реальном пользовательском скриншоте готовой СОП «Копия СОП поверка электроинструмента с проб(002).xlsx» в шаге 1 видны >3 ключевых моментов: текст каждого нумерованного КМ занимает несколько визуальных строк. Stage42 разделял по каждой новой строке и блокировал импорт при >3; принятая Stage41 обрезала нормализованные КМ до трёх.
- **Реализовано в отдельной Stage42 ветке PR #40:** `stage42SplitKeyMoments()` выделяет КМ по реальным номерам 1., 2), 3. и т. д., объединяет мягкие переносы внутри каждого пункта и не путает их с десятичными числами. Без нумерации обычные переносы не превращаются в несколько пунктов.
- **Интерфейс:** каждый КМ — отдельная пронумерованная textarea, можно редактировать, добавлять, удалять и вставлять номерной список; перенос из ячейки теперь использует общий парсер. Порог **3 КМ больше не вызывает запрета**. Для подозрительно больших списков есть лимит 60 с явным сообщением.
- **Совместимость:** `stage42-apply.js` переносит все КМ без `.slice(0,3)`, а Stage42 wrapper вокруг `normalizeStepShape()` обеспечивает сохранение >3 КМ при перезагрузке/библиотеке, при этом исходные 73 модуля принятой Stage41 не меняются. В редакторе доступно добавление КМ после третьего. Корпоративский XLSX выводит все КМ с нумерацией в прежней ячейке, однако физический перенос/высоту строк при длинном списке проверить на заводском файле.
- **QA:** `qa/stage42_key_moments_browser.py` + `tests/test_stage42.py`; запуск Linux/Windows `.github/workflows/stage42.yml`: 5+4+1 пунктов, переносы, inline-нумерация, десятичные значения, импорт, редактор, библиотека и обратный XLSX. Финальный CI проверить по SHA перед выдачей сборки; синтетический XLSX, реальная книга по скриншоту не передана.
- **Документ:** [STAGE42_XLSX_IMPORT_WIZARD_RU.md](STAGE42_XLSX_IMPORT_WIZARD_RU.md). Main Stage41 не менять и PR #37 карты не трогать.
