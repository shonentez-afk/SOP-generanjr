Подтверждено локальными проверками JS и Chromium с ограничениями среды. `tools/build_stage12.py` воспроизводит релиз из базовой Stage 11 и отдельных модулей. Описание: `docs/RELEASE_STAGE12_RU.md`.

**Нельзя изменять настройки ИИ, исходный прокси Yandex Cloud, модели, промпты и маршрутизацию запросов без отдельной команды пользователя.**

## Начальный эталон
`releases/stage11-photo-editor.html` — перенесённый из предыдущего чата исходник Stage 11 с редактором фотографий. Эта версия — baseline для регрессии, не заявлять полное функциональное тестирование без фактического запуска.

## Запреты
- Не переписывать бизнес-логику при структурном разделении; сначала сохранить поведение.
- Не ломать поля СОП, порядок шагов, фотографии, связку с ФРВ, TWI, экспорт/импорт XLSX, библиотеку и архив.
- Не менять структуру IndexedDB/localStorage, ключи, версии документов без миграции.
- Не менять способ запуска (один HTML, без веб-сервера).
- Не добавлять реальные персональные данные, фото, внутренние СОП, секреты и API-ключи в Git.
- Отделять неподтверждённое от проверенного; не выдавать план за реализацию.

## Порядок при продолжении
1. Прочесть README.md, этот файл, CURRENT_STATUS_RU.md, ARCHITECTURE_RU.md и CHANGELOG_RU.md.
2. Проверить состояние ветки/PR/CI и фактический код; не полагаться только на чат.
3. Сопоставить сборку с baseline: проверка равенства/осмысленного diff и регрессионные сценарии.
4. Выполнять изменения в отдельной ветке, затем PR; зафиксировать тесты и обновить CURRENT_STATUS_RU.md.
5. После каждого этапа приложить готовый HTML и отметить текущую версию, SHA и ограничения.

Выполнить **пакет A** из `docs/DEVELOPMENT_PLAN_MODULAR_AI_TWI_20261119_RU.md`: завершить перенос большого src/legacy JS в логические исходные модули, заменить цепочку текстовых патчей единым детерминированным сборщиком, стабилизировать границы состояния/медиа/Excel/ИИ, запустить E2E и выпустить один автономный HTML.
