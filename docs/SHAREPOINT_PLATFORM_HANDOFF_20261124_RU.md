### 1. Цели и ограничения

Пользователь хочет развить существующий конструктор в единую платформу с одним стартовым экраном:
- Библиотека стандартов СОП, их утверждённых редакций и архива.
- Библиотека TWI с привязкой к конкретной версии СОП.
- Производственный аудит первого уровня L1/LPA: чек-листы, результаты, замечания, ответственные, корректирующие действия.
- Инструменты: прежний конструктор СОП, TWI из СОП, ИИ, ФРВ, редактор фотографий, печатные XLSX.
- Поручения, встречи и уведомления сотрудникам через классический Outlook и Exchange.

**Важное решение пользователя:** отдельный корпоративный SharePoint-сайт не дадут. Всё размещается во **вновь созданном дочернем сайте личной области** пользователя. Не предлагать снова отдельный корпоративный сайт, не удалять уже созданное.

### 2. Подтверждённое состояние SharePoint по скриншотам

1. Интерфейс классического SharePoint, напоминает SharePoint Server 2016. Версия сервера **не проверена**.
2. Сайт **«Платформа СОП и TWI»** уже создан как дочерний сайт в персональной области; имя URL — **sop-platform**.
3. В «Содержимом сайта» уже существуют **«Библиотека СОП»** и **«Библиотека TWI»**. На момент снимка обе содержали **0 элементов**. **Не создавать повторно.**
4. Доступны «Добавить приложение», «Параметры», «Страницы сайта», «Активы сайта».
5. Открывались параметры «Библиотеки TWI» и пункт «Параметры управления версиями». На снимке было: «Требовать утверждения контента» = **Нет**, «Создать основные версии» = **выбрано**, «Хранить 10 основных версий» = **галочка установлена**, «Требовать извлечения» = **Нет**.
6. Пользователю рекомендовали снять ограничение в 10 основных версий, но **нет подтверждения сохранения страницы**. При случае перепроверить.
7. **ПОСЛЕДНИЙ СКРИНШОТ** — экран «Создать столбец» для библиотеки TWI: имя пустое, «Однострочный текст» уже выбрано, обязательность «Нет», уникальность «Нет», максимум 255 знаков, значение по умолчанию пустое, галочка добавления в представление стоит.
8. **ПЕРВЫЙ СТОЛБЕЦ ЕЩЁ НЕ ПОДТВЕРЖДЁН СОЗДАННЫМ**: последняя фотография — форма до сохранения.

### 3. БЛИЖАЙШЕЕ ДЕЙСТВИЕ: создать «Номер TWI»

Продолжать точно с открытой страницы «Создать столбец» библиотеки TWI:

| Настройка | Значение |
| --- | --- |
| Имя столбца | **Номер TWI** |
| Тип | **Однострочный текст** |
| Описание | Номер инструкции TWI для учёта и поиска |
| Требовать обязательного заполнения | **Нет** |
| Применять уникальные значения | **Нет** |
| Максимальное число знаков | **255** |
| Значение по умолчанию | **Пустое** |
| Добавить в представление по умолчанию | **Да** |

Затем прокрутить вниз и нажать **«ОК»**. По следующему скриншоту убедиться, что столбец добавлен. Не включать обязательность и уникальность: существующая Stage41 ещё не формирует независимый номер инструкции TWI.

### 6. Что уже реально работает в SOP-generanjr Stage41

Принятая Stage41 — автономная HTML-программа для ПК в Chrome/Edge, **73 активных JS-модуля**.

- Редактор СОП: действие, ключевые моменты, причины WHY, фотографии, критерии; в корпоративском формате **одно поле причины**, допускаются нумерованные причины внутри этого поля.
- ИИ и полная проверка СОП через действующий Yandex Cloud Functions proxy. **Не менять конфигурацию ИИ и прокси.**
- TWI формируется **из текущего СОП**, после чего его можно корректировать; нет отдельного конструктора TWI с нуля.
- Печатные XLSX: СОП на 3 листах, TWI на 2 листах. Локально встроены ExcelJS и пиктограммы ISO 7010.
- ФРВ и отдельный Анализ ФРВ. Не требовать обязательной связки ФРВ → СОП → TWI.
- Существующая библиотека на IndexedDB: черновики, опубликованные и архивные документы, история редакций, JSON-резервирование, отдельные сценарии сетевой папки.
- **Внутри снимка СОП хранятся данные TWI.** Отдельная версия TWI как самостоятельный документ SharePoint — задача будущей интеграции.

**Не реализовано:** API-хранение в SharePoint, перенос существующих данных, самостоятельная TWI-библиотека в приложении, единый портал на главном экране, производственный L1-аудит и обмен заданиями с Outlook.

Исходные файлы: README.md; docs/START_NEW_CHAT_RU.md; docs/USER_GUIDE_STAGE41_RU.md; src/app/stage41-parts.json; releases/stage41-ai-quality-20261123.html в ветке main.

### 7. L1-аудит — два разных понятия

В Stage41 уже существуют **документы** docs/AUDIT_LEVEL1_STAGE41_RU.md и docs/AUDIT_LEVEL1_USER_GUIDE_STAGE41_RU.md — функционально-архитектурный аудит **самой программы**, а не производственная инспекция.

**Производственный аудит первого уровня L1/LPA** (проверки рабочего места, OK/NG/N/A, фото, ответственные, сроки, корректирующие действия) запланирован как **новый модуль**. Не заявлять, что он уже реализован.

### 8. Outlook/Exchange: запланировано, не реализовано

Пользователь подтвердил: **классический Outlook с вкладкой «Файл»**, корпоративский Exchange. Тип Exchange (локальный Server или Exchange Online) пока не выяснен.

Предусматриваются:
- Штатные задачи и встречи Outlook со ссылкой на конкретный СОП/TWI/аудит.
- Возможный локальный Windows-модуль Outlook Bridge (интерактивное управление Outlook COM).
- Позднее при наличии разрешений — серверная интеграция Exchange.
- Завершение задачи Outlook **не должно** автоматически утверждать СОП или закрывать производственный аудит.

Сейчас никакой обмен задачами, встречами или уведомлениями программно не подключён.

### 9. Ограничения и безопасность

- Сайт расположен в личной области по требованию пользователя. Нужны резервные копии, управление правами, учёт зависимости от аккаунта владельца и план переноса данных.
- Не публиковать внутренние URL SharePoint, логины, персональные и производственные данные, настоящие документы и цеховые фотографии в открытом GitHub.
- По виду сайта нельзя достоверно установить точную версию SharePoint или доступность REST API, Script Editor, Content Editor, SPFx. Всё тестировать отдельно.
- Для возможной интеграции применять API SharePoint с текущими разрешениями пользователя, не подменять права.
- Сначала только учебные документы, затем проверки версий, прав, ссылок, восстановления фото, импорта/экспорта и конфликтов.
- Не менять принятую Stage41 и шаблоны XLSX без отдельной ветки и регрессии.
