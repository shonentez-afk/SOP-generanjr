# Stage38 — пронумерованные причины без изменения корпоративного XLSX

Дата начала: 23.11.2026. **База**: принятая пользователем Stage37 в main, PR #33 merged (103/103 tests, Linux/Windows PASS).

## Утверждённое корпоративное правило

**В каждом шаге остаётся одно поле `reason` / «Причина».**
- Допускается одна общая причина без нумерации.
- Если причины различны, автор может записать в одном поле `1. Причина\n2. Причина\n3. Причина`.
- Количество перечисленных причин не обязано строго совпадать с числом ключевых моментов: одна причина может объяснять несколько моментов; проверяем только явные странности нумерации, а не выдумываем отдельные строки.
- Поле причины — текст без новых структурных ключей, внешних API, таблиц и дополнительных Excel-столбцов.

## Изменения

1. `src/modules/quality/stage38-reasons.js` — анализ явно пронумерованных строк, сохранение исходных переводов строк, отсечение только **редакционных** номеров `1.`, `2.` от проверки числовых фактов, расчёт высоты существующей печатной строки.
2. Промпты `stage19-prompts.js` и `stage29-prompts.js` — объясняют разницу между общей причиной и нумерованными различными причинами; при доработке ИИ не отменяет уже указанную пользователем нумерацию. Действующие Yandex AI прокси, параметры и ограничения остаются без изменений.
3. `stage29-quality-core.js` — сохраняет переносы строк ИИ в `reason`, не считает `1.\n2.` вымышленными техническими числами, **не ослабляет** проверку фактических допусков, значений, времени и параметров. Нумерация не создаёт разрешённые числа для других полей TWI.
4. `stage28-core.js` — в уже существующей «Полной проверке СОП» показывает замечания при пропущенных/дублирующихся пунктах и явном несоответствии; общей причине без нумерации замечание не предъявляется. Автоматических правок нет.
5. `stage34-steps.js` — только одно, чуть более высокое редактируемое поле «Причина» с короткой подсказкой.
6. **Корпоративный XLSX:** `stage34-export.js` — сохраняет все три исходных листа СОП, ФРВ, Чек-лист, ширины колонок, объединённые ячейки, картинки/якоря, формулы, печать и стиль; при необходимости **увеличивает только высоту уже существующей строки «Причина»**. Свыше 29 измеренных строк предупреждает об объёме вместо молчаливой обрезки. Редактирование и состояние СОП не изменяются при экспорте.
7. **TWI XLSX:** `stage36-1-print-xlsx.js` — сохраняет те же два печатных листа; переносит содержимое единственного поля причины и добавляет предупреждения о явных ошибках нумерации.

## Проверяем до слияния с main

- Сравнение реального `SOP.xlsx` от Stage37 и Stage38 через **openpyxl**: совпадающие наборы листов, объединения, ширины, области/параметры печати, формулы, стили и количество фотографий; для трёх длинных причин выросла **только высота строки**; текст и номера находятся в одной ячейке.
- Проверка реального TWI JI XLSX A4 и его двух листов с длинными нумерованными причинами, плюс сохранность исходного СОП/TWI после обоих экспортов.
- Экспорт с одной общей причиной не требует нумерации; дубли/пропуски номеров показываются только как замечания.
- ИИ с причинами `1. ...\n2. ...` проходит проверку, но число `25 Н` без исходного подтверждения всё равно отклоняется.
- Полная регрессия Stage37 и всех более ранних тестов: Chrome `file://`, IndexedDB, FRV, фото/ISO7010, СОП и TWI, Windows/Linux.
- Руководство/передача следующему чату обновлены в ветке.

## Что специально НЕ меняем

- Число полей, колонок/листов корпоративного XLSX и их взаимное расположение.
- Номера и хранилище сохранённых СОП, структуру `steps[].reason`, переходы между версиями.
- Настройки Yandex Cloud прокси, AI-маршрутизацию, фирменные фотографии/ISO, импорт/ФРВ.
- Печать TWI и принципы четырёх этапов наставника.
