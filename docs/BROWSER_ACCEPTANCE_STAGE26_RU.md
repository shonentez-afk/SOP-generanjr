# Конструктор СОП — приёмка Stage 26 в вашем браузере

**Версия:** `releases/stage26-final-browser-candidate.html` · ПК, Chrome/Edge, автономный `file://` · один HTML. Это готовая версия для пользовательской проверки после принятия GitHub CI.

## Что уже проверено автоматически

- Воспроизводимая сборка 50 JS-модулей в один HTML; неизменны локальная ExcelJS, 60 ISO 7010, встроенные стили и редактор фото.
- Полная регрессия Chrome на Linux: Excel с фотографиями, JSON, библиотека и история наставника, исправление `null`, TWI, СОП, ФРВ.
- Защита данных: запоздалые ответы не применяются; отмена предпросмотра ничего не меняет; RAW, подтверждённые времена ФРВ и ссылки на фото остаются неизменны.
- Контракты HTTP/JSON: отмена по таймауту при чтении ответа, ограничение размера, корректная классификация ошибок, fallback только при доказанной ошибке модели. Прокси, набор моделей, промпты и формат тела запроса остались прежними.
- Windows GitHub-hosted Chrome: запуск по `file://` без сервера и доступа к интернету, 60 ISO, ExcelJS, основные экраны, локальный черновик и внутренняя проверка библиотеки.

## Что необходимо сделать на вашем компьютере

Работайте с тестовым документом, не с действующим опубликованным СОП.

### 1. Запуск файла и локальные ресурсы

1. Откройте в GitHub `releases/stage26-final-browser-candidate.html` и используйте **Download raw**. Сохраните файл локально, например в «Загрузки».
2. Откройте его двойным щелчком в **Chrome или Edge для ПК**. Адрес должен начинаться с `file:///`; сервер и соседняя папка с JS не нужны.
3. Проверьте вкладки «Редактор», «ФРВ», «TWI», «Документы». Откройте пиктограммы безопасности: они должны появляться сразу, без обращения к интернету. Убедитесь, что кнопка «Разметить» открывает редактор снимка.

### 2. Настоящее соединение с Yandex Cloud (единственный внешний тест ИИ)

1. При подключённом интернете нажмите **«Проверить AI»** в верхней панели.
2. Убедитесь, что статус становится «AI: доступен» и нет сообщений 401/403/404/429.
3. При ошибке сохраните **текст сообщения**, название выбранной модели, время запроса и скриншот; если пользуетесь DevTools, можно приложить HTTP-статус без ключей/токенов и персональных данных.
4. Сделайте один тестовый запрос. Приложение не должно переключать модель на 401/403/429/общий 5xx; переключение допустимо только при явно указанной недоступности модели. Не запускайте многократные запросы подряд при ошибке тарификации.

### 3. СОП, наставник и фотографии

1. В «Редакторе» заполните «Описание процесса», например: «Перед запуском проверить защитное ограждение, целостность кабеля и отсутствие людей в опасной зоне».
2. Нажмите **«Сгенерировать СОП по описанию»**. Для пустого документа шаги создаются сразу.
3. В одном шаге измените действие и время. Добавьте настоящее фото, нажмите **«Разметить»**, внесите видимую отметку и сохраните.
4. Снова нажмите генерацию: должен открыться предпросмотр. Сначала выберите **«Оставить текущий СОП»** — шаги, время и фото не меняются. Затем повторите и выберите **«Добавить новые шаги»** — старый шаг и фото остаются. «Заменить весь СОП» проверяйте только после сохранения тестовой копии.
5. Нажмите **«Проверить весь СОП»**. Проверяйте замечания по безопасности, времени и Key Points. Если ответ ИИ не содержит готового значения, не должно быть блока «Готовое исправление: null» и кнопки «Применить».
6. Оспорьте одно замечание, затем сохраните черновик и повторно откройте документ. История диалога должна сохраниться.

### 4. TWI автоматически из СОП

1. Перейдите на TWI и нажмите **«Сформировать план TWI»**. ФРВ для этого не требуется.
2. Проверьте заполнение всех четырёх этапов Job Instruction.
3. Измените вручную одно поле в плане TWI. Отредактируйте исходный шаг СОП и вернитесь на TWI: появится уведомление об устаревании.
4. Сформируйте TWI ещё раз. Должно открыться сравнение «Сейчас / Предложение ИИ». Ручное исправление по умолчанию не должно быть выбрано для замены. Нажмите отмену — старый текст останется; затем испытайте выборочное применение.

### 5. ФРВ: фактические замеры должны быть защищены

1. На вкладке исследования ФРВ нажмите **«Построить ФРВ из описания»** (при пустом исследовании).
2. Впишите фактически измеренное время, например **43 секунды**, и комментарий наблюдателя.
3. Для строки используйте кнопку **«Подсказать»**: должен появиться предпросмотр. Проверьте отмену, «Заполнить только незаполненные» и явно подтверждаемую замену производных полей.
4. Нажмите **«Анализировать ФРВ»**. В предпросмотре доступны сохранение только анализа, заполнение пустых полей, замена пояснений и отмена.
5. Повторите **«Построить ФРВ из описания»**: предложения можно добавить отдельным циклом, без удаления прежних наблюдений.
6. После каждого действия исходное RAW-действие, ваши **43 секунды**, комментарий и привязанное доказательство должны оставаться на месте. Новому AI-циклу длительность не присваивается автоматически.

### 6. Excel, локальная библиотека и сетевая папка

1. В «Документах» выберите **«Скачать XLSX»**. Откройте в Microsoft Excel и проверьте, что фотография действительно встроена в нужный шаг, а не отображается только как ссылка.
2. Выполните **«Сохранить черновик»**, закройте и снова откройте тот же HTML в том же профиле браузера; проверьте восстановление текста и изображений.
3. Нажмите **«Запустить проверку»** в разделе «Проверка библиотеки» и сохраните результат. Проверьте импорт/экспорт «JSON с фото», не работая с производственными документами.
4. Если используете корпоративную папку, сначала подключите её в Проводнике Windows как сетевой диск (например, `X:\СОП`). В разделе «Папка хранения» нажмите **«Выбрать папку»**, затем **«Проверить доступ»** и **«Синхронизировать»**. Chrome/Edge может спросить разрешение на доступ к файлам — подтвердите вручную.
5. Повторно откройте тестовый документ и убедитесь, что синхронизировался именно он. Проверьте «Проверить целостность» и наличие резервной копии, если функция была использована.

## Критерий приёмки

**Готово**, если основные операции выполняются без JS-ошибок, Excel содержит фото, ручные изменения СОП/TWI/ФРВ не исчезают, диалоги предпросмотра отменяются без изменения данных, локальная библиотека сохраняет черновик и внешний ИИ отвечает через ваш текущий прокси. Сетевая папка проверяется только если она доступна на вашей машине.

**При ошибке:** сообщите точный шаг из этой инструкции, ожидаемое и полученное поведение, браузер/версию Windows, текст сообщения и скриншот. Для ошибок XLSX приложите тестовый XLSX без конфиденциальной информации. Не передавайте токены прокси, пароли, персональные данные и внутренние производственные материалы.

## Границы автоматической приёмки

GitHub Actions не имеет доступа к вашему корпоративному сетевому диску и учётным данным Yandex Cloud. Поэтому тест настоящего прокси и вашей сетевой папки выполняется **только на вашем компьютере**. Это не недоделанный код, а отдельная проверка реальных внешних условий эксплуатации.
