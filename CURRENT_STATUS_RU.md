# Текущий статус TWI Audit

**Дата фиксации:** 2026-11-18
**Ветка:** `project/twi-audit-20261118`
**Версия:** RC1 / ограниченный пилот
**Production-ready:** нет, до фактической проверки на рабочих устройствах

## Подтверждено

1. Статический HTML и локальный JSON, миграция schemaVersion 2→3.
2. Версионность чек-листов и защита исторических аудитов от подмены критериев.
3. Управляемые корректировки журнала с причинами и сохранением истории.
4. Мобильное сохранение/экспорт/импорт с дедупликацией.
5. Основные аналитические и отчётные сценарии проходят синтетические smoke-тесты.
6. Предрелизный QA RC1 пройден в моделируемом окружении, подробности в отчёте.

## Требует проверки в пилоте

- Локальная работа с JSON на реальных корпоративных ПК; восстановление после отказов файловой записи.
- Импорт мобильных пакетов на реальных моделях телефонов и используемых браузерах.
- Полные пользовательские сценарии: создание → сохранение → корректирующее действие → последующий аудит → отчёт → backup/restore.
- Проверка приватности и защиты URL AI-функции до эксплуатации с реальными данными.
- Повторные аудиты: корректность эффективности при недостатке данных.

## Основные риски

- Один JSON на несколько параллельных операторов: возможны потери обновлений — использовать единственного записывающего.
- Очередь мобильной версии в localStorage: очистка браузерных данных может уничтожить непереданное.
- Открытый облачный endpoint: риск посторонних вызовов и расходов.
- Ручные резервные копии требуют дисциплины.

## Правила дальнейших изменений

- Не менять настройки AI/прокси без явного требования.
- Не смешивать несовместимые критерии v1/v2 в статистике.
- Сначала корректность расчётов и сохранения, затем UX.
- Каждую модификацию тестировать, обновлять QA/Changelog и документы для нового чата.
- Ветку конструктора СОП не трогать.
