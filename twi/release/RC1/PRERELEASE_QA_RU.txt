ОСТАВШИЕСЯ ОГРАНИЧЕНИЯ ПИЛОТА
1. Одна основная база JSON не предназначена для одновременной записи с нескольких ПК. Мобильные устройства должны передавать пакеты через импорт.
2. HTTP URL Cloud Function фактически публичный. CORS не является аутентификацией. Если URL станет известен третьей стороне, возможны чужие вызовы и расходы AI. API-ключ Yandex при этом остаётся только в Function.
3. Мобильная очередь хранится в localStorage браузера телефона. Очистка данных браузера удалит ещё не экспортированные аудиты. В пилоте важно регулярно экспортировать очередь.
4. Поведение скачивания файлов / localStorage на телефоне необходимо проверить на конкретных корпоративных моделях и браузерах.
5. L2/L3 пока являются календарным контролем факта выполнения; отдельных утверждённых цифровых чек-листов L2/L3 нет.
6. Резервные копии создаются вручную. Автоматического фонового backup без сервера в текущей архитектуре нет.
7. Сравнение аналитики между разными версиями чек-листа намеренно не выполняется: v1 и v2 анализируются раздельно.

РЕКОМЕНДУЕМЫЙ ПИЛОТ
- 1 основной ПК / 1 владелец twi_data.json;
- 2–3 внутренних тренера;
- 5–10 инструкторов;
- 2–4 недели;
- минимум 20–30 реальных L1-аудитов;
- 1–2 мобильных устройства;
- резервная копия перед началом пилота и не реже одного раза в неделю;
- фиксировать найденные дефекты отдельно, не менять структуру JSON вручную.
