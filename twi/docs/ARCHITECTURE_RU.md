# Архитектура TWI Audit RC1

## Deployment

Один автономный HTML в Chrome/Edge; JSON-база (`schemaVersion: 3`) через File System Access API; генерируемая мобильная HTML-форма хранит очередь в localStorage. Опциональная Yandex Cloud Function для AI-отчётов, без публикации API-ключа браузеру.

## Модули

1. Справочники сотрудников и версий чек-листа.
2. Чек-лист TWI JI L1: четыре шага, 20 критериев (7+4+4+5).
3. Журнал и редактирование с причиной/историей.
4. Дашборд, профили инструкторов, матрица, динамика.
5. Корректирующие мероприятия и оценка эффективности.
6. Каскад контрольных сроков L2/L3.
7. Руководитель/тренер/инструктор: отчёты и AI summary.
8. Import/export, резервное копирование, целостность.
9. Мобильная автономная форма.

## Инварианты

- Каждый аудит связан с собственной `checklistVersion`. Старые критерии нельзя подменять новыми.
- Аналитика различных версий не смешивается.
- Аннулированные аудиты сохраняются для истории, но исключаются из текущих показателей.
- После закрытия корректирующего действия эффективность проверяется по последующим аудитам того же инструктора и критерия, с учётом версии.
- Перенос мобильных записей проверяет дубликаты и версии.
- Реальные цифровые чек-листы L2/L3 отсутствуют, их не выдумывать.

Конечный HTML остаётся однофайловым; внутреннюю разработку можно модульно организовать с последующей упаковкой, сохранив контракт запуска.
